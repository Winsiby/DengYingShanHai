# 《灯影山海》夸父形象考据与模型规格

> 版本日期：2026-10-01  
> 用途：约束夸父角色的视觉设计、建模、关节、材质、动画和参赛表述  
> 原则：先证据、后设计；历史原文与可核验古图优先，不以搜索结果热度或个人审美代替依据。

## 1. 当前结论

夸父不再使用“通用古代男性皮影”直接代替。最终角色采用：

> 《山海经·海外北经》《山海经·大荒北经》的文字特征 + 清代《古今图书集成·神异典》所载《夸父神图》的公版轮廓 + 中国皮影的关节与透光媒介特征，重建为可实时投影的 2.5D 关节皮影模型。

这一路线不是照抄现代网络插画，也不是宣称复原某一地方皮影流派，而是“有原典和古图依据的当代数字皮影改编”。

## 2. 原典证据

### 2.1 《海外北经》：玩法和叙事的直接依据

维基文库公版文本：<https://zh.wikisource.org/wiki/山海經/海外北經>

原文包含：

> 夸父与日逐走，入日。渴，欲得饮，饮于河、渭，河、渭不足，北饮大泽。未至，道渴而死。弃其杖，化为邓林。

同一段之后还记载夸父国之人“为人大”，并写到右手青蛇、左手黄蛇。该句描述对象是夸父国之人，不应未经说明就等同为夸父本人。

可直接落实到游戏的硬锚点：

| 原文要素 | 游戏落实 | 不应擅自增加的结论 |
|---|---|---|
| 与日逐走 | 太阳/灯源成为目标，第二幕形成追日姿态 | 不把它改写成战斗或击败太阳 |
| 河、渭不足，大泽未至 | 通过风、步伐、呼吸和节奏表现体力消耗；不新增取水支线 | 不扩展为完整饮水任务系统 |
| 弃其杖 | 手杖必须是独立、可见、可操控的核心道具 | 不把手杖降级为纯装饰 |
| 化为邓林 | 第三次互动的直接结果必须是落杖后生林 | 不只在通关字幕后播放无因果特效 |

### 2.2 《大荒北经》：造型辨识度的直接依据

维基文库公版文本：<https://zh.wikisource.org/wiki/山海經/大荒北經>

原文直接描述夸父：

> 有人珥两黄蛇，把两黄蛇，名曰夸父。

因此以下特征属于文本证据，不是设计者凭空增加：

- 人形；
- 耳侧两条黄蛇；
- 手中另有两条黄蛇；
- 与追日、河渭、大泽和死亡叙事相连。

原文没有规定发式、面容、具体衣制、甲胄、皮肤颜色和肌肉结构，因此不能把某张现代插画中的这些细节说成“《山海经》原貌”。

## 3. 网上形象候选的可审计筛选

### 3.1 筛选门槛

候选图只有同时经过以下检查，才可能成为模型的直接造型来源：

1. 页面明确说明所画对象是夸父，而不是泛称上古巨人；
2. 出处、年代或作者至少有一项可核验；
3. 图像许可允许改编和进入游戏，或作品已经进入公有领域；
4. 有足够清楚的完整人物轮廓；
5. 与原典冲突的部分能够被识别和剔除。

“图片好看”“搜索排名高”“被转载很多”不作为入选理由。

### 3.2 候选比较

| 候选 | 出处与许可 | 可核验性 | 用途结论 |
|---|---|---:|---|
| 《夸父神图》PNG | 《古今图书集成·博物汇编·神异典》，约 1700–1725；Wikimedia Commons 标为 Public Domain Mark | 高 | **主视觉依据**；保留原始线描轮廓和时代图像证据 |
| 《夸父神图》SVG | 上述古图的自动矢量化版本；页面同样标为公有领域 | 高，但矢量化质量需检查 | **建模轮廓起点**；须对照 PNG 清理自动描摹错误 |
| `Kua-fu.gif` | Commons 页面称来自 illustrated Shan Hai Jing，年代标为“16th century?”，并标注公有领域 | 中低，来源和作者带问号且只有 351×205 | 只作古图差异比较，不作唯一模型底稿 |
| 河南焦作龙源湖公园夸父逐日像照片 | 2025 年照片，CC BY-SA 4.0 | 照片来源清楚，但现代雕塑本体权利与造型作者信息不完整 | 只研究追日动作和体量感，不复制雕塑造型、贴图或几何 |
| The Met/Wikimedia 中国皮影图版 | 馆藏/CC0，但人物并非明确夸父 | 许可高，角色身份低 | 只研究皮影关节、镂空、色片和操纵结构，不再作为夸父主轮廓 |
| 商业插画站、百度图片、Pinterest、影视与游戏截图 | 多数缺少原作者或可改编许可 | 低 | 排除；不进入概念图拼贴、贴图、模型或宣传物料 |

主参考：

## 4. 事实、历史图像与创意改编的边界

| 层级 | 可以写入参赛说明的内容 | 处理规则 |
|---|---|---|
| 原典事实 | 追日、饮河渭而不足、赴大泽未至、弃杖化林、珥两黄蛇、把两黄蛇 | 原文可引用短句并注明篇名 |
| 历史图像依据 | 角色轮廓参考《古今图书集成》中的《夸父神图》 | 保存来源页、公版标记和下载日期 |
| 媒介研究 | 关节铰接、镂空、透光色片、操纵杆来自中国皮影媒介研究 | 不宣称复原某一地域流派，除非后续有该流派专家/馆藏证据 |
| 项目改编 | 将手持黄蛇简化为前臂盘绕的蛇形构件，使双手可以操杖；将角色改造成 2.5D 可投影模型 | 必须明确写成“为互动与皮影操纵进行的创意改编” |
| 技术实现 | UE 真实阴影、参数判定、Control Rig、三幕状态机、Sequencer | 属于团队程序和演出贡献 |

## 5. 最终角色造型规格

### 5.1 轮廓与结构

- 整体轮廓以《夸父神图》为起点，不套用通用武士、野蛮人、孙悟空或现代奇幻英雄模型。
- 人物采用正侧之间的皮影视角，优先保证投到幕布上的头、胸、手杖和迈步姿态可辨。
- 保留耳侧两条黄色蛇形构件。
- 原典“把两黄蛇”在互动版本中转译为左右前臂各一条可辨的盘绕蛇形构件，以释放双手操持手杖；开场定格画面可以短暂恢复手持姿态，表明改编来源。
- 手杖单独建模、单独碰撞、单独状态，不与手掌永久合并。
- 不增加铠甲、长剑、法器、王冠和兽头肩甲等原典没有、又会造成角色误读的元素。
- 发式、衣纹和面部以古图可辨内容为准；如果原图无法支持某个细节，就用简化皮影轮廓，不从现代商业插画补齐。

### 5.2 2.5D 模型而非写实全身模型

采用薄片式 2.5D Skeletal Mesh：玩家在幕后能看到皮影实体和关节，幕前看到真实灯光投射的影子。

建议构件：

1. 头部；
2. 发饰/耳侧蛇形件；
3. 胸腹/骨盆主体；
4. 左右上臂；
5. 左右前臂；
6. 左右手；
7. 左右大腿；
8. 左右小腿与足；
9. 左右前臂蛇形构件；
10. 独立手杖；
11. 必要的镂空装饰片。

每个可动片在关节处保留重叠，避免旋转后漏出空洞；重叠铆点在幕后可见，在幕布投影中形成皮影媒介特征。

### 5.3 命名和技术规格

| 资产 | 建议名称 | 规格 |
|---|---|---|
| 角色模型 | `SK_DY_Kuafu_Puppet` | 单一 Skeletal Mesh；薄片深度只用于可靠投影和侧面可见性 |
| 骨架 | `SKEL_DY_Kuafu_Puppet` | Root、Pelvis、Spine、Head、双臂、双腿、蛇形件和 Staff 控制骨；不做面部骨骼 |
| Control Rig | `CR_DY_Kuafu_Puppet` | 灯前平移、朝向、迈步、前倾、举杖、落杖、跌落/定格控制 |
| 手杖 | `SM_DY_Kuafu_Staff` 或独立 Skeletal Mesh | 可从手部释放；第三幕拥有明确落点与落地事件 |
| 主材质 | `M_DY_Puppet_Master` | 支持不透明/透光色片、双面显示、颜色参数和阴影开关 |
| 材质实例 | `MI_DY_Puppet_Kuafu` | 主体赭色/暗红；黄蛇保持可辨；颜色属于项目视觉改编，不宣称原典规定 |
| 调试姿态 | `DA_DY_KuafuPoseDebug` | 保存三幕目标姿态、关节范围和投影验收参数 |

性能基线：

- 一个角色，不制作面部表情系统；
- 目标三角面控制在约 8,000–20,000，薄片轮廓优先于表面细节；
- 最多一张 2048 颜色/透明图集，必要时另加一张遮罩；
- 不依赖布料物理；飘带或蛇形件只用少量骨骼和受控动画；
- Shipping 包内不携带未使用的高精度原图和建模中间缓存。

这些数值是实时演示的工程预算，不是历史形象判断；最终以目标电脑性能测试为准。

## 6. 三幕所需动作，不扩展成通用动画库

| 阶段 | 必需动作 | 目的 |
|---|---|---|
| 引日启幕 | 静立、抬头/伸手、灯前位置与朝向响应 | 让玩家发现光源与投影规律 |
| 逐光成形 | 前倾、长步、双臂与手杖协同、短暂失衡 | 形成“追日”而不是普通行走的剪影 |
| 杖落成林 | 举杖、落杖/植杖、力竭定格、手杖脱手 | 让第三次操作直接造成树林生长 |

不购买通用战斗动作包，不制作攻击、受击、翻滚、攀爬、武器连招和面部对白动画。

## 7. 免费/开源建模和绑定路线

### 主路线：公版 SVG → 2.5D 关节模型

1. 下载《夸父神图》PNG 和 SVG，并保存许可页面。
2. 对照 PNG 清理 SVG 的自动矢量化错误。
3. 按皮影关节重新切分轮廓，补充原典要求的四条黄蛇和独立手杖。
4. 在 Blender 中为各片增加极薄厚度和必要倒角。
5. 使用简单骨架做刚性或近刚性权重。
6. 导出 FBX，在 UE 5.8 中建立 Control Rig。
7. 在真实灯光、幕布和参数判定同时开启的测试场景验收。

Blender 为自由开源工具；矢量清理可以使用 Inkscape。工具免费并不自动决定输入素材许可，因此输入仍严格限制为公版、CC0 或自有素材。

### 备选：MakeHuman/MPFB 只作人体比例辅助

MakeHuman/MPFB 官方许可页面说明核心图形资产为 CC0，软件代码分别采用 GPL/AGPL：<https://static.makehumancommunity.org/about/license.html>

如果古图轮廓难以直接产生稳定骨架，可以用 MakeHuman 输出作为关节位置和人体比例辅助，再把最终外轮廓压平成皮影薄片。它不替代《夸父神图》，也不直接决定服装和装饰。

### UE 内绑定与动画

Epic 的 UE 5.8 Control Rig 文档说明可以直接在 Unreal Editor 中创建控制和动画：<https://dev.epicgames.com/documentation/en-us/unreal-engine/control-rig-in-unreal-engine>

Epic 也提供免费 Control Rig/Mannequin 示例，可用于理解双足角色的控制和 Sequencer 工作流：<https://www.unrealengine.com/blog/free-control-rig-and-mannequin-asset-packs-now-available-for-real-time-animators>

示例只作技术参考；最终夸父采用自己的薄片骨架和关节范围。

## 8. 模型验收标准

模型只有同时满足下列条件才可进入主关卡：

- 能从来源表逐项说明头部、蛇形件、手杖和总体轮廓依据；
- 没有照搬无授权现代插画、雕塑或商业游戏角色；
- 幕后近看能识别关节、铆点、色片和操纵结构；
- 幕前仅看影子时，三名首次体验者中至少两名能从“追日、手杖、太阳”语境判断为夸父，而不是武士或普通旅人；
- 耳侧黄蛇与前臂蛇形件在幕后可辨，投影中不要求每条蛇都独立辨认；
- 三次互动复用同一 Skeletal Mesh、Control Rig 和状态系统；
- 手杖能可靠附着、释放、落地并触发第三幕；
- 极端关节角不会破面、穿帮或造成阴影大面积跳变；
- Development 与 Shipping 包中的视觉投影一致；
- 资产来源、许可证据、改编说明和 AI 使用记录已归档。

## 9. 对外表述模板

推荐：

> 夸父形象以《山海经·海外北经》《大荒北经》为文字依据，以公版《古今图书集成·夸父神图》为历史图像参考，结合中国皮影的关节与透光结构重建为可实时操控的 2.5D 数字皮影。项目对黄蛇持握方式、关节结构和手杖控制进行了适配互动的当代改编，并通过 Unreal Engine 实时灯光生成幕布阴影。

禁止：

- “完全还原上古夸父真实形象”；
- “复原某某地区非遗皮影”，但没有对应流派专家和馆藏依据；
- “角色为团队从零原创”，却不披露古图底稿；
- “所有素材均为原创”，但使用了公版图像、开源工具和第三方环境资产。
