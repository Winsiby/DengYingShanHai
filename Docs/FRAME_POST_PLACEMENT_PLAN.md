## 2. 实测尺度：不把源模型或灰盒尺寸当正式设计

实际导入檐柱总高 `2036.121966 cm`、柱身直径约 `200 cm`、柱础总宽 `285.278183 cm`。单位和轴向经源数据与 UE 实读确认，不能猜为毫米。

现有接收体包围盒为 `X[925,975]、Y[-450,450]、Z[-50,750] cm`；地面顶为 `Z0`。因此总高 8 米，但**地面以上的幕顶是 7.5 米**。这仍是已有 Dev 大接收体，不是正式小剧场尺度。

完整离线推导位于 `Saved/Audit-2026-10-12-FramePostPlacementPlan/FRAME_POST_PLACEMENT_NUMERICAL_BASIS-RUN2.json`。它重新解析原始和派生 FBX 的真实顶点、多边形及材质分区，不仅比较整柱包围盒。槽 0 为柱身 33 个多边形，槽 1 为柱础 65 个多边形；输入前后 SHA 一致。

两个候选的整柱、柱身和柱础 AABB 均未与报告枚举的 13 个旧接收体/障碍/右屏风包围盒，或保护盒 `X[-440,975]、Y[-470,470]、Z[-70,770]` 相交或接触。13 项为 BackScreen、左右 Boundary、CameraWall、InnerCornerA/B、LowCeiling/PostA/B、Step1/2/3、WingScreen_Right。地板顶面的落地接触是预期，不在这 13 项排斥检查内；其余组件、角色胶囊、碰撞代理与相机路径没有据此逐形状/逐通道验收。这里只证明冻结变换下的包围盒分离，**不证明镜头无遮挡、玩家可达、Visibility 射线不受影响、位于主灯光锥外或真实阴影合格**。柱础距离保护盒仅约 14 cm；改变位置、旋转或比例必须重算并实读运行 bounds。

柱身距幕侧边仍约 51 cm，柱础约 34 cm，不能称为已经接合的承托框。不为补缝临时新增横梁、拉伸幕布或隐藏灰盒。

## 4. 最小架构与实施前冻结项

后续样本使用一份独立 Dev 地图副本，不改变当前 `LV_EnvironmentStatesLab` 或旧固定包。该副本只是开发对照，不增加竞赛主场景。

- 仅新增一个原生 `StaticMeshActor`，显式引用现有檐柱和两个常量 MI；无新 C++ 类、蓝图事件图、Director/Stage 绑定、Controllable、Tick、Timer、扫描、Subsystem 或第二套流程状态。
- 七份已通过准入的资产及其哈希冻结。若确需调整纹理密度，先在新 Dev 专用常量 MI 中比较，不覆盖当前准入实例，也不把地板平铺值搬到柱子。
- 原 33 个 Actor 的完整可观测合同、地图身份与依赖必须冷读并留证。主灯、五态环境灯、曝光、相机、接收体、输入、音频、脚步、跨幕解除、15 Hz、目标/容差/保持、A 端/Z70 和真实成林全部保持。
- 写地图前记录唯一位置候选、总高、旋转、均匀比例、落地 Z、Actor 标签、组件所有权及实际 world bounds。左右侧是镜头问题，不用包围盒对称性替代画面选择。
- 明确 Static/Mobility、Collision Profile 名称、ActorCollisionEnable、有效 CollisionEnabled、ObjectType 和全部通道响应（尤其 Pawn、Camera、Visibility）、复杂/简单碰撞来源、CastShadow、动态间接与距离场影响。源导入没有自动生成碰撞；不能仅设 BlockAll 后便声称玩家不会穿模。阻挡玩家还依赖真实可用形状与胶囊双方响应；Camera=Ignore 也不能被记为镜头防穿通过。
- 不因“不想影响谜题”直接推断应关闭所有阴影，也不因“真实材质”直接开启所有光照影响。若先做非碰撞/不投影的纯构图比较，必须明确它只验外观；若测试真实柱影，则需单独证明主灯全过程无玩法遮挡。两者不能互代。

本机原生源码还限定了光照隔离的说法：网格 `bGenerateMeshDistanceField=false` 仅表示没有开启该资产的强制生成选项；当前项目 `r.GenerateMeshDistanceFields=True` 时仍可能生成距离场，不能写成“模型不存在距离场”。依据为 `Engine/Classes/Engine/StaticMesh.h` 1290–1295 与 `Engine/Private/StaticMesh.cpp` 4564–4566。当前 `r.Lumen.TraceMeshSDFs=0`、GI/ReflectionMethod=1、`r.RayTracing=False` 也不能推导出新增物件没有任何间接/反射影响。`PrimitiveComponent.h` 的 `bVisibleInReflections` 注释明确屏幕空间追踪直接采 SceneColor，不受该开关保证隔离。本轮不改这些全局配置；后续对比组件开关与真实画面，并把结论限定到实际测试过的路径。

本轮仅形成上述合同，没有执行 Actor 属性设置或选择最终碰撞/阴影策略。Routine 文件检查不需重复审批；正式尺度迁移、核心设施修改或未有实测依据的体验权衡仍须与用户确认。

更详细的两种互斥碰撞/投影候选及原生源码依据，分别保存在同一审计目录的 `FRAME_POST_DEV_POLICY_READONLY_REVIEW.md` 和 `FRAME_POST_COLLISION_CONTRACT_READONLY_REVIEW.md`。这些也是只读建议，不是新场景已测报告。

## 5. 质感与文化边界

柱的作用是给影戏演出面提供克制、可信的空间边界，而非以装饰数量代替“以灯为日、以影为夸父”的核心文化创意。原亭台下载页的“复原”宣传不能作为本项目历史、建筑年代或特定皮影流派的依据。

当前 Dark Wood 是真实免费 PBR 输入，但 1×1 采样只是方向比较：物理纹理密度、柱顶端面、柱脚、法线正负方向的实际光照响应、近中远细节和接缝均未正式验收。槽 0 的 `(V,1-U)` 与法线 `(-Ny,Nx,Nz)` 应保持一致；旋转参数仅使用已支持的 0/1 端点，不能用中间值当连续旋转。

继续保持 Surface/Opaque/DefaultLit、单面、`r.Substrate=0` 和原曝光，不新增 WPO、Emissive、Bloom、雾、运行时动态 MI 或新插件来掩盖问题。若柱础看起来像木材而不适合最终艺术方向，应据真实材质槽和免费来源单列替换候选；不假称当前材质已是历史正确石础。

## 6. 后续实际测试与交付门槛

1. **准入与保护**：核对免费许可、派生记录及七资产哈希；冻结旧 33 Actor、产品、包和来源，列精确新 Dev 文件白名单与回退。
2. **实际场景冷读**：核对新 Actor 唯一性、变换、落地、材质槽、包围盒与碰撞/光照属性；不能猜 `.uasset` 节点。
3. **真实画面**：五态同一最终 POV、出生点/灯/偶操纵位、行走近中远、主灯与偶控制极值、Holding/打断及完整 Drop→Contact→Forest。同时看清幕后原因、目标参考、地线和真实影形。接触、树形展开与完成提示不抢拍。
4. **流程回归**：两轮三幕、重演、R、跨幕退出操纵、E 对焦与遮挡、有声/静音、真实位移脚步。历史测试计数仅作基线，新样本需真正运行对应测试。
5. **性能与质量**：在目标机记录真实 RHI、分辨率、同 POV 基线与候选帧时/GPU/显存；不能以低三角数、材质编译或文件准入替代性能和作者审美验收。
6. **独立包**：通过源码/场景测试后才用明确新 Dev 地图 Cook，检查实际依赖及 UFS，生成新的 Windows Development 固定版本；实测启动、首帧和退出。旧包及旧启动入口不改，失败记录不清理。

后续才考虑构件是否值得进入正式幕框、再筛选横梁与布质侧幕。本轮不预建空启动器，不宣称完整剧场、Shipping、第二台电脑、5–8 分钟盲测或正式美术完成。
