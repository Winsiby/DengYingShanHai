# INTERACTION & PRESENTATION SPEC｜核心互动与声画演出规格

## 1. 文档目的

本文把《灯影山海》的五项核心优化落实为可开发、可测试、可降级的规格：

1. “弃杖化林”是第三次互动的直接因果结果；
2. 三次互动形成“发现规律 → 协同控制 → 综合运用”的学习曲线；
3. 游戏画面持续保留“幕后实体—幕上影像”的双重空间；
4. 锣鼓点、吟唱、风声、脚步和枝叶声共同建立演出节奏；
5. UE 真实阴影负责玩家所见，参数区间负责稳定通关，并提供 Development 调试证据。

本文不增加第四个谜题、新场景、战斗、分支剧情或新的输入体系。唯一人类负责人为用户本人，统一负责程序、表现、美术、音频和过程素材；Codex 仅按授权辅助，不依赖其他制作成员。

这里的“不增加新场景”指不增加第二主地图或新关卡；同一戏台扩展为连续小剧场的空间、美术与最小叙事规格见 [`ENVIRONMENT_NARRATIVE_SPEC.md`](ENVIRONMENT_NARRATIVE_SPEC.md)。

## 2. 最终体验闭环

```text
玩家操作灯/偶
    ↓
真实 UE 光源立即改变幕上阴影
    ↓
同一组灯、偶、姿态参数进入目标容差
    ↓
趋势反馈 → Holding → Resolved
    ↓
冻结玩家最终状态与落杖接触点
    ↓
手杖落下并在接触帧发出木击/锣鼓重音
    ↓
林影从同一个接触点生长
    ↓
风声、枝叶声、吟唱与灯色共同进入高潮
```

逻辑成功、视觉阴影和高潮演出共享同一次玩家操作，但三者职责分离：

- `ADYPuzzleDirector` 只决定条件是否成立；
- Movable 主灯、皮影和幕布生成实时视觉结果；
- `BP_DYStagePresentation` 只在 Director 确认后编排镜头、动画、音频和 VFX；
- Sequencer 不得直接修改谜题完成状态。

## 3. 三次互动的学习曲线

### 3.1 总览

| 互动 | 学习角色 | 玩家控制 | 必要条件 | 认知任务 | 成功回报 |
|---|---|---|---|---|---|
| 引日启幕 | 发现规律 | 主灯单轴/受限轨道 | 灯位置，必要时加宽松角度 | 发现“灯动，影变” | 日轮归位、第一声木击与鼓点唤醒戏台 |
| 逐光成形 | 协同控制 | 主灯 + 夸父位置/朝向或预设姿态 | 灯条件 + 偶条件 + `PoseId` | 在幕后两个简单调整之间来回协同 | 奔跑影形接续、脚步和呼吸形成追逐节奏 |
| 杖落成林 | 综合运用 | 同一主灯 + 同一夸父 + 已学姿态切换 | 灯、偶、落杖姿态和保持时间 | 组合已学能力完成神话因果 | 手杖接触点直接长出林影并进入高潮 |

难度来自条件组合和叙事压力，不来自更窄容差或新增按键。第三次互动的数值容差应与第二次相当或略宽。

### 3.2 互动一：发现规律

玩家可见结果：移动灯具时，日轮位置、夸父投影比例或山影关系立刻变化。

设计约束：

- 只开放一个主要连续变量；
- 初始画面故意处在“明显不对但方向可读”的状态；
- 玩家第一次有效调整后，目标山纹、幕布暖光或木击声给出弱反馈；
- 不在开场直接显示数值、箭头仪表盘或完整答案轮廓；
- 若玩家长时间无有效进展，再逐级增强环境提示，而不是弹出长教程。

退出条件：首次玩家能够用自己的话说明“移动灯会改变幕上的日和影”。

### 3.3 互动二：协同控制

玩家可见结果：灯负责“日与投影尺度/方向”，皮影负责“夸父位置、朝向或姿态”，两者必须共同构成追逐关系。

设计约束：

- 一次仍只操纵一个对象，玩家用同一套交互键在灯和偶之间切换；
- 不开放自由骨骼编辑，只提供轮廓差异明显的少量姿态；
- 已正确的单项可以出现柔和稳定反馈，但不能提前判定整个谜题成功；
- 允许软吸附或分段停靠，避免来回调整时已经正确的变量频繁漂移；
- 脚步、呼吸和鼓点随“接近—Holding—完成”逐层加入，不按每帧进度连续触发音效。

退出条件：首次玩家理解“灯决定光影关系，偶决定角色动作”，并能主动在两个对象之间切换。

### 3.4 互动三：综合运用

互动三不增加新的交互语法。推荐操作顺序是：

1. 调整主灯，让“日”落到终章构图区域；
2. 调整夸父位置/朝向，保留追逐方向；
3. 切换到持杖/落杖姿态，使杖尖进入接触区域；
4. 所有条件同时有效后进入 Holding；
5. 玩家维持结果，完成落杖因果。

允许通过演出提示建议上述顺序，但 Director 仍按最终全部条件判定。已接近正确的条件使用滞回、软吸附或更宽退出容差保护，避免玩家在切换对象时反复从零开始。

退出条件：玩家认为自己“让手杖落下并长出了树林”，而不是“完成对齐后看了一段树林过场”。

## 4. “弃杖化林”的直接因果实现

### 4.1 成功链

第三次谜题必须采用以下顺序：

```text
P03 全部必要条件有效
→ Holding 完成
→ Director 生成并冻结 Resolved Snapshot
→ 禁止继续改动灯/偶，但保留其最终 Transform
→ Stage Presentation 从当前画面启动落杖动作
→ 杖尖/接触锚点到达幕布落点
→ 同一帧触发木击重音与 BeginForestGrowth
→ 林影从该落点向外生长
→ 幕布、灯色、声音和镜头扩展为 Finale
```

禁止做法：

- 成功后把灯和皮影瞬移到另一套预制构图；
- 黑屏后从无关位置播放树林动画；
- 由 Sequencer Event Track 直接调用“完成谜题”；
- 在没有手杖接触画面的情况下全屏淡入树林；
- 跳过过场后让树林或结束状态缺失。

### 4.2 表现锚点

`ADYShadowPuppetActor` 或其 Blueprint 子类提供一个稳定的杖尖表现锚点，例如骨骼 Socket 或 Scene Component。该锚点只服务表现，不参与主判定。

`BP_DYForestGrowthActor` 是放置在主关卡中的表现 Actor：

- 由 Stage Presentation 直接引用，不自行搜索 Director；
- 接收落点 Transform 或使用配置好的幕布接触锚点；
- 提供幂等的 `BeginGrowth` 与 `ApplyCompletedState`；
- 只控制林影材质、Niagara、几何动画或预制皮影片段；
- 不保存谜题状态，不决定通关。

最终落点必须与目标参数调出的杖尖位置在视觉上重合。若资产动画无法精确匹配，优先调整皮影 Socket、动画终点或目标参数，不用全屏特效掩盖错位。

### 4.3 跳过、重置和中断

- P03 Resolve 后不允许局部重置回未完成状态；“重新体验”走完整流程重启；
- Finale 被跳过时，调用统一收尾函数并立即应用树林、灯光、幕布和音频的最终一致状态；
- Sequencer 停止、角色销毁或关卡退出时，清理输入锁、临时音频和镜头所有权；
- `BeginGrowth`、Finale 入口和收尾函数都必须防止重复调用；
- 音频或 VFX 加载失败不能阻止完成界面出现。

## 5. 幕后与幕上的双重空间

### 5.1 空间职责

- 幕后空间回答“玩家操纵了什么”：灯具、皮影、操杆、关节、舞台结构；
- 幕上空间回答“这些操作变成了什么”：日轮、夸父、山形、手杖和树林；
- 戏台周边空间回答“这场演出发生在哪里”：入场短廊、台翼、锣鼓角、观演区与远山共同形成完整小剧场；
- 两个空间必须在核心操作时保持可推理关系，而不是只在结尾补拍说明镜头。

### 5.2 镜头所有权

采用稳定的传统运行时架构：

- 自由观察：角色的 Camera Component/Spring Arm 提供基础视角；
- 操纵对象：本地 `PlayerController` 切换到放置的 `BP_DYStageCameraRig`；
- 短过渡/高潮：Stage Presentation 启动带 Camera Cut Track 的 Level Sequence；
- 任一时刻只有一个系统拥有最终 POV；不用 Experimental Gameplay Camera System；
- Sequencer 完成、跳过或中断后，由统一函数恢复当前有效的舞台镜头或角色 View Target。

`BP_DYStageCameraRig` 的构图采用幕后侧后方的三分之四视角：幕布是主要阅读区，同时让主灯、皮影或操杆至少有一项保留在前景/侧景。先确定机位、遮挡和主体，再调 FOV/焦距；不通过极端广角或景深掩盖空间问题。

### 5.3 镜头状态

```text
Explore
  → BlendToStageInteraction
  → Manipulate
  → BlendToShortTransition / BlendToFinale
  → RestoreStageOrExplore
```

规则：

- 操纵期间相机稳定，先保证幕布和被操纵实体同时可见，再考虑轻微呼吸感；
- 不在基础机位稳定前叠加 Camera Shake、Lag 或强景深；
- 正确趋势只允许轻微构图/光线强化，不让相机运动代替反馈；
- 谜题成功可以使用一次短推进或侧移，随后清楚回到下一交互机位；
- Finale 至少包含一个不切镜的因果镜头：玩家最终影形 → 杖尖落点 → 林影生长；
- 相机震动强度必须可降至零，不能影响影子辨认。

### 5.4 双空间验收

- 任一互动录制 10–20 秒无切镜片段，都能同时看见幕后操作对象与幕上结果；
- 测试者不看说明文字也能指出“哪一盏灯、哪一个偶”造成当前影子；
- 角色、相机、灯具网格和操杆都不会遮挡目标核心区域；
- 常用分辨率和画面比例下，幕布目标、交互提示和字幕都处于安全区；
- Finale 的 Camera Cut Track 结束、跳过和异常中断均能恢复正确 View Target 与输入。

## 6. 声音演出与节奏

### 6.1 声音分层

| 层 | 内容 | 驱动方式 | 功能 |
|---|---|---|---|
| 空间底层 | 戏台木结构、微风、远处环境 | Stage Presentation 的循环 Audio Component | 建立空间，避免全程绝对静默 |
| 操作拟音 | 灯架摩擦、操杆、衣料、脚步 | 交互事件或 Animation Notify | 证明幕后实体正在被操纵 |
| 谜题节奏 | 木击、鼓点、锣点、呼吸 | Puzzle 状态事件和进度分段 | 表达接近、Holding 与完成 |
| 叙事声部 | 原创非语义吟唱/经核验唱段 | 过渡和 Finale 的 Audio/Sequencer Track | 提升神话与皮影演出感 |
| 自然回报 | 风增强、树枝伸展、叶片簌动 | 杖尖接触与 Forest Growth 事件 | 把落杖和成林连成因果 |

若使用具体地域的传统唱腔、锣鼓经或现成录音，必须核对地域、语义、表演者和授权。资料不足时使用作者创作的非语义人声与原创打击节奏，不宣称其为某一传统流派原貌。

### 6.2 三段声音弧

**引日启幕**

- 开场以微风、木结构和远处低频建立沉寂；
- 第一次有效移动触发轻微灯架/木轴声音；
- 接近目标时加入稀疏木击，不连续轰鸣；
- Holding 使用稳定但克制的单层鼓脉冲；
- Resolve 用一次明确锣点或木击结束句子。

**逐光成形**

- 皮影姿态变化通过操杆、衣料或关节声表现；
- 脚步使用 Animation Notify 对齐动作，不由 Puzzle Progress 每帧驱动；
- 接近时加入呼吸和更密鼓点；
- Holding 建立短暂追逐节奏，取消时自然回落；
- Resolve 后的迈步、山纹移动和声画节拍必须对齐。

**杖落成林**

- 组合调整阶段让风声、低声吟唱和鼓点逐层聚拢；
- Holding 完成后先保留极短呼吸空间，再让手杖落下；
- 杖尖接触帧是唯一强重音，同帧触发木击/低鼓与林影生长；
- 枝干扩展使用低频木裂/伸展，叶片出现后加入高频簌动；
- Finale 再加入完整吟唱和锣鼓层，不能在接触前提前泄露高潮。

### 6.3 技术规则

- `OnPuzzleProgressChanged` 先在 Stage Presentation 中转换为有限的“远/近/有效”音频状态，使用滞回和冷却，禁止每帧播放 One Shot；
- `OnPuzzleHoldStarted/Cancelled` 控制可平滑进入/退出的节奏层；
- `OnPuzzleResolved` 只触发一次段落重音；
- 脚步、杖尖接触等精确同步声音使用 Animation Notify 或 Sequencer 中明确的同步点；
- Audio Component 和 Sequence Player 的绑定、停止和解绑必须有对称生命周期；
- 音效不是唯一提示：静音时仍能通过影子、材质和 UI 完成全部谜题。

## 7. 真实 UE 阴影与参数判定分层

### 7.1 渲染与曝光假设

当前 Windows Demo 的首选基线：

- Deferred Renderer；
- 一盏 Movable 主灯产生关键实时阴影；
- 优先测试 Virtual Shadow Maps 作为主灯阴影路径；
- Lumen GI/Reflections 可用于环境反弹和质感，但不是判定依赖；
- 单主灯场景默认不启用 MegaLights，只有目标机测量证明有收益时才评估；
- 互动阶段使用固定曝光或窄范围受控曝光，避免灯具移动引起亮度泵动；
- 灯具强度必须连同灯型、物理单位、距离、Source Radius、曝光和目标硬件一起调试，不孤立填写强度数字。

主灯优先采用与道具形态相符的 Spot Light 或 Point Light，并开启动态阴影。Attenuation Radius 只限制影响范围，不作为亮度旋钮；Source Radius 越大阴影越软，因此从能保持皮影关节和杖尖轮廓清楚的较小值开始，再按锯齿和艺术目标逐步调整。

### 7.2 幕布与关键阴影

- 幕布材质必须在目标观察侧清楚接收/表现真实主灯阴影；
- 皮影主体、手杖和关键操杆使用稳定几何轮廓并明确 Cast Shadow；
- 装饰灯、氛围材质、Light Function 或预制林影片段可以增强演出，但不能替代玩家操纵产生的主轮廓；
- 目标纹样与实际阴影使用不同视觉语言，避免玩家把提示误认为真实投影；
- 录屏和现场版保留同一主灯/主阴影路径，画质降级时优先牺牲次要灯、粒子、景深和环境阴影。

### 7.3 逻辑判定

主判定只读取：

- `LightPosition` / `LightRotation`；
- `PuppetPosition` / `PuppetRotation`；
- `PoseId`；
- 当前谜题允许的控制掩码；
- 连续保持时间。

主判定不读取：

- 屏幕颜色；
- 阴影像素；
- 后处理结果；
- 当前分辨率或抗锯齿结果；
- 音频/Sequencer 播放进度。

视觉与逻辑之间通过同一灯/偶状态建立因果，而不是通过像素识别建立依赖。任何可选 Mask 分数都只能用于实验性辅助反馈，关闭后仍必须完整通关。

### 7.4 Development 调试显示

`WBP_DYDebug` 至少显示：

- 当前 `PuzzleId`、学习阶段和谜题状态；
- 每个启用条件的 Current、Target、Enter Tolerance、Exit Tolerance 与 Valid；
- `PoseId` 当前值/目标值；
- 总体 Progress、Holding 已用/所需时间；
- Active Interactable、Enabled Control Mask；
- 最近一次状态迁移和 Resolve 次数；
- P03 的冻结 Snapshot、杖尖/幕布接触锚点是否有效；
- 当前 View Target、是否由 Sequencer 接管；
- 主灯实时阴影是否启用、当前画质档与帧时间摘要。

可选世界调试图形包括受限轨道、目标区间、幕布接触点和杖尖锚点。它们只在 Development/显式调试模式出现，不进入 Shipping，也不能修改实际判定。

### 7.5 灯光诊断顺序

1. 暂时关闭会掩盖问题的风格化后处理；
2. 锁定曝光；
3. 检查幕布与皮影材质/法线；
4. 检查 HDR/Eye Adaptation；
5. 检查 Lumen Overview/Surface Cache；
6. 检查 Shadow/VSM 可视化和主灯影响范围；
7. 检查 Light Complexity 与局部灯重叠；
8. 在目标电脑记录 GPU 时间和目标画质档；
9. 逐层恢复后处理、雾和次要灯。

## 8. 类、所有权与通信

| 对象 | 类型/生命周期 | 唯一职责 | 通信 |
|---|---|---|---|
| `ADYPuzzleDirector` | 主关卡 World Actor | 谜题定义引用、运行状态、参数评估、Holding、Resolve、调试快照 | 对 Stage Presentation/HUD 发动态多播委托 |
| `ADYMovableLightActor` | 放置 Actor | 灯具约束、归一化参数、真实灯光组件 | 参数变化委托；不依赖流程 |
| `ADYShadowPuppetActor` | 放置 Actor | 皮影约束、`PoseId`、姿态表现锚点 | 参数变化委托；不决定谜题 |
| `BP_DYStagePresentation` | 主关卡 Blueprint Actor | 表现状态、音频层、Sequence 播放与统一收尾 | 绑定 Director 一次；直接引用表现 Actor/资产；使用 Token 回调 |
| `BP_DYStageEnvironment` | 主关卡表现 Actor | 收拢剧场环境灯、材质与台翼/题签状态 | 由 Stage Presentation 直接调用；不读取 Director |
| `BP_DYStageCameraRig` | 放置 Blueprint Actor | 操纵时的稳定双空间构图 | 由本地 PlayerController 切换 View Target |
| `BP_DYForestGrowthActor` | 放置 Blueprint Actor | 从落点执行一次林影生长与最终状态 | Stage Presentation 直接调用 |
| `WBP_DYDebug` | Development Widget | 只读显示调试快照 | 查询 Director/订阅状态，不扫描世界 |

选择直接引用和发布者委托的原因：项目只有一个主地图和一套明确对象关系。这里不需要 Subsystem、全局消息总线或 `Get All Actors of Class`。Stage Presentation 在 BeginPlay 查询当前状态后只绑定一次，结束或销毁时解除绑定；Stage Environment 只被动应用 Dormant、SunAwakened、ChaseAwakened、FinaleReady 与 ForestComplete 表现状态。

## 9. 失败与降级

| 风险 | 最小降级 | 不得牺牲 |
|---|---|---|
| 主灯阴影性能不足 | 降低次要灯/粒子/后处理/环境阴影质量 | 主灯对夸父、手杖和幕布的实时投影 |
| 幕布材质透光表现不稳定 | 使用更稳定的双面受光方案并减少复杂材质层 | 玩家操作与幕上轮廓的直接可见关系 |
| Finale VFX 性能不足 | 用材质参数和少量预制林影替代高密度 Niagara | 林影必须从杖尖接触点开始 |
| 过场镜头中断 | 统一收尾并直接应用最终状态 | 输入恢复、正确 View Target、树林结果 |
| 音频资源延期 | 使用原创木击、鼓、风和叶声最小组合 | 接触重音、Holding 节奏和静音可玩性 |
| 玩家频繁调丢已正确条件 | 加大 Exit Tolerance、软吸附或分段停靠 | 仍由玩家完成最终组合 |
| 周边环境削弱幕布焦点 | 减少局部灯、装饰动态阴影和高对比细节 | 主灯、幕布、夸父和杖尖的视觉层级 |

## 10. 验收矩阵

### 互动与因果

- [ ] 三关分别能被首次玩家概括为发现规律、协同控制和综合运用；
- [ ] 第三关不新增按键或第四套机制；
- [ ] P03 Resolve 后保留玩家的最终灯/偶状态，不瞬移换景；
- [ ] 林影从杖尖接触点开始，接触声与生长首帧同步；
- [ ] Finale 跳过或中断后仍得到一致的树林与结束状态。

### 双空间与镜头

- [ ] 操纵镜头同时看见至少一个幕后原因和幕上结果；
- [ ] 10–20 秒无切镜录屏能证明实时因果；
- [ ] PlayerController、舞台相机和 Sequencer 不会同时争抢 POV；
- [ ] 结束、跳过、重启和窗口失焦后 View Target/输入均恢复；
- [ ] 无强景深、抖动或遮挡影响目标辨认。
- [ ] 入场、台翼、台前和远景扩展没有改变核心操纵机位的幕后/幕上可读性。

### 声音

- [ ] 风、脚步/操杆、锣鼓、吟唱、枝叶各有明确进入时机；
- [ ] 进度变化不会造成 One Shot 连发；
- [ ] 杖尖接触帧有唯一强重音，高潮不会提前泄露；
- [ ] 静音状态下三关仍可完成；
- [ ] 所有录音、音乐和唱段来源/授权已登记。

### 阴影、判定与调试

- [ ] 主灯为真实 Movable UE 光源，关键皮影实时 Cast Shadow；
- [ ] 固定/受控曝光下影子轮廓稳定，无明显亮度泵动；
- [ ] 调低视觉质量不会改变参数判定结果；
- [ ] Development 能显示全部条件、滞回、Holding、状态和 P03 Snapshot；
- [ ] Shipping 不显示调试层、目标区间或跳关入口；
- [ ] 目标电脑完成三轮连续通关和至少一次 Finale 性能采样。
