# 《灯影山海》项目宪法（Spec Kit）

**版本**：1.0.0 ｜ **批准日期**：2026-10-20 ｜ **适用范围**：`D:\灯影山海` 全部 Spec Kit 特性

本宪法高于任何 `plan.md`、`tasks.md`；与其冲突的实现方案必须改写。

## 一、不可让渡的产品事实

1. **单一主地图**：正式可玩内容只存在于 `/Game/DengYingShanHai/Maps/L_DY_Main`。任何扩景先落在 `/Game/DengYingShanHai/Dev/WorldV2/` 隔离图，合并前必须有可回退副本。
2. **三幕骨架不变**：引日启幕 → 逐光成形 → 杖落成林。判定参数（P01 灯≈0.68/保持 1.25s；P02 灯≈0.72 + 偶≈0.80 + 跨步；P03 偶≈0.85 + 灯≈0.72）与 Director 流程不得为美术让路。
3. **视觉阴影与判定分离**：UE 实时灯影负责观感，成功判定只依赖参数区间与持续确认，不得改为像素/阴影比对。
4. **既有谜题 Actor 不得搬家**：主灯、幕布、皮影、操杆、A 端接触点、Guide 的 Transform 与引用链保持原值；扩建筑只能在其包围盒之外生长。
5. **菜单视觉冻结**：主菜单为 `DYDevEntryWidget` 的既定版式（底图 + 六牌匾 + 说明牌），本轮只接功能，不改配色、字号、位置、动效。

## 二、工程与资产纪律

6. **真机验证优先**：任何"完成"必须附真实运行证据（截图/日志/包内实测），不接受仅编译通过。
7. **可回退**：改动前记录涉及文件；地图与二进制资产改动前留副本；不得执行破坏性 Git 操作、不得公开推送。
8. **资产许可**：只使用团队自制或明确 CC0/OFL 资源；每项外部资产登记来源、Commit、许可与所用文件，未核验即不得进 `Content/`。
9. **隔离导入**：外部资源先进 `D:\灯影山海\ExternalAssetStaging\`，筛选后按 `/Game/DengYingShanHai/Art/WorldV2/` 归档，禁止覆盖 `Stage/`、`Maps/`、`UI/Menu/` 既有源文件。
10. **无付费依赖**：不引入付费模型/插件/服务，不为一次性需求新增运行时插件。

## 三、能与不能

11. **不臆测蓝图**：无法直接审查的 `.uasset` 内部节点不做假设，只通过 `BlueprintCallable`/`BlueprintReadOnly`/事件接口对接，并给出搭建步骤与验收方法。
12. **单一 POV**：PlayerController、舞台相机、Sequencer 任一时刻只有一个最终视角所有者。
13. **表现层不夺权**：外景反馈只能订阅已验证的阶段完成事件（`BP_DYStagePresentation` 同层），不新建第二套谜题推进器，不 Tick 扫描世界。
14. **不做范围外扩张**：开放世界、战斗、联机、任务系统、多结局、第二座戏台均不在本轮；新增想法只进"范围外候选"。

## 四、交付定义

15. **可运行包才算交付**：Windows 包能在目标机启动，并在包内完成"菜单 → 三幕 → 成林 → 重演"。
16. **证据成套**：每个里程碑留下截图、日志、差异清单与回退路径；报告须写明"改了什么/怎么测/还剩什么风险"。
17. **时间闸门**：2026-10-20 23:59 前，任何单项外部依赖卡住超过 45 分钟即降级为 UE 原生方案。
