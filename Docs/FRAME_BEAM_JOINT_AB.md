## 3. 为什么只建议B继续进入Dev

源面覆盖从8.754%增加到48.212%，结合实图右接合更容易读懂，可以作为下一独立可玩候选的依据。但当前梁X厚度仍窄于柱顶，B未覆盖整个柱顶；右柱顶约23.106168cm的Y范围仍不被梁底覆盖。增加材质细节不能改变这些几何条件。

“保幕宽”在这里严格指**全梁外轮廓仍跨原900cm幕宽**，不是梁底覆盖幕全宽。B左端尖部刚到幕边，下斜端内收，底面左端缺27.367484cm。这是有代价的候选，而非所有条件同时改善。正式选择不能仅凭面积百分比或这组诊断截图。

当前文化创新仍是“以灯为日、以影为夸父”和玩家直接落杖成林；木构要服务演出和幕后／幕上关系，不把CC0构件摆放说成历史复原、真实榫卯或正统流派。

## 4. 材质与镜头边界（技能核查记录）

- 材质架构保持旧常量MI→旧父材质→三张木材纹理，不建通用Master、MID、MPC、函数或新层。沿用既有Surface／Opaque／DefaultLit／单面与r.Substrate=0记录；本轮不重新编译或认证材质图。
- 既有UV0→QuarterTurn1 `(V,1-U)` 与NormalDX `(-Ny,Nx,Nz)` 保持；本轮图片只支持可见长向／纵向纹，没有材料参数修改。纹理导入色彩空间、采样和内存预算继承原准入记录，不冒称本轮重新测量。
- 唯一变化参数是Editor内存的ActorY，单位cm；向+Y增加会扩大右接合、缩小左端覆盖余量。X／Z／Scale／Euler/quaternion不放行，主灯和曝光不写。
- 同比例／同材质仍不意味着纹理密度相同，柱约259.60、梁顶140.11、侧／底198.15源texel/m沿用旧数据，非实际游戏mip。旧父材质没有Tiling参数，不仅新建MI假修密度。
- 本轮不增加shader permutation、WPO、RVT、透明重叠或材质参数变体；没有测GPU／内存／实时流送，不能据此说性能零影响。梁位置变化可能影响未关闭的渲染路径，不能笼统声称所有GI／反射不变。
- 摄影由专用LevelEditor viewport拥有；无PIE、CameraActor、Controller／CameraManager写入或Sequencer，没有新的最终POV所有者。只临时取景后恢复原视口；无lag／shake／镜头切换／后处理改动。
- 镜头技能使A/B同机位、游戏与诊断镜头分离；材质技能使“接合问题”和“纹理问题”分开验证，避免通过换光／提亮或改旧共享材质掩盖几何问题。
