# 《灯影山海》单人制作规则

更新：2026-10-09。来源：用户明确要求“本项目全靠我一个完成”。

## 1. 人员事实与责任

用户本人是唯一人类作者与项目负责人。程序、架构、策划、关卡、资产筛选和适配、灯光、声音、动画、录屏、视频、封面、许可及参赛材料均由同一作者负责。不存在第二名美术、声音或视频制作人员。

Codex、WorkBuddy 是辅助工具，不是制作成员。当前工具执行模式是用户后续授权的 Codex 直接实现、测试和文档辅助；WorkBuddy 仅在用户另行明确指定的任务中使用，保留短摘要加本地文件的输入限制。不虚构 AI 执行、人工通关或外部协作记录。

## 2. 适合单人且不会建模的制作路线

- 优先获取许可清晰的免费/开源成品与可拆分基础资源，不采购付费资产或服务。
- 筛选、裁剪可见部分、统一材质、比例、枢轴和构图，再在独立 Dev 场景验收；不把全部手工建模或绘制作为默认任务。
- 夸父形象与皮影结构依文化依据核对；专属适配方案先确认，不把通用巨人或其他地域皮影直接当夸父。
- 原始资源与适配产物分开保留。准确登记来源、作者、许可、修改、引擎用途和 AI 使用，不能把外部模型、字体或声音冒称原创建模/书法/表演。
- 核心灯偶幕、三段因果和真实阴影优先；P1/P2 装饰依既有止损规则评估。单人事实不自动批准删机制、改节奏或降低成品质感。

## 3. 工作推进

每轮只选一个可验证的关键路径，明确唯一工具执行者、源码/资产白名单、备份与验收。先完成底层与 Dev 验证，再集成正式表现。不安排不存在的人员并行交付。

真人键鼠体验、盲测和最终提交由作者确认。可以邀请未参与开发者提供测试反馈，但测试者不是制作成员。自动脚本、真实画面、键鼠操作和包内通关分别记录。

## 4. 署名与历史文件

提交署名仅填用户真实姓名（由用户填写），具体个人贡献、第三方资产与 AI 工具使用分栏列出。旧文档中由“队友”承担的当前任务全部归用户；历史过程报告和 Saved 审计不追溯改写，不能把过去的未触碰范围或工具记录伪造成新事实。

部分历史文档及许可模板尚未完成逐项同步，以本文件和最新 AGENTS.md 为当前人员事实源。未完成同步不表示外部许可已经签收。

## 5. 当前已批准的下一步

独立 Dev 的开始—三幕—结束—重演闭环：同一地图显示开始面板，点击后才启动第一幕；真实成林完成后提供重演，重新加载当前地图清除旧会话。只增加菜单鼠标操作，不改 E/A/D/R、参数、镜头或正式美术，不做暂停或 Skip。

该隔离 Dev 闭环已实现并完成原生回归、两轮可见流程、同地图重载和独立 Development 包首帧检查。真人按钮及键盘全流程仍由用户签收；不等于成品美术、5–8 分钟体验或正式竞赛版本已经完成。具体状态及证据见 DEV_ENTRY_LOOP_PLAN.md 与 DEV_ENTRY_LOOP_VALIDATION.md。
