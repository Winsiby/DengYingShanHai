# 幕框与台翼｜下一阶段结构方案

日期：2026-10-11。用户是唯一人类作者与负责人；Codex负责辅助实现、测试和证据，不依赖其他制作成员。

## 1. 玩家可见结果

把现有裸露影幕逐步变为“有支撑、有边界、有后台原因”的影戏演出面：克制木框说明幕布的承托关系，暗红/深色侧幕形成台翼层次，中央继续读出灯、偶、操杆和真实影形。先完成主体轮廓与接缝，再考虑少量装饰；不摆满新道具、不把西式金饰或泛亚洲纹样当文化创新。

此阶段没有新的谜题、输入、镜头、场景、流程时间或声景。第三幕仍从玩家实际最终灯偶状态落杖成林。本轮已完成候选准入审查，尚未完成框架模型集成；不把本计划写成运行功能。

## 2. 资源路线与降级

采用“精选免费构件＋项目适配”，不直接搬入整套剧院/亭子。木构与布质资产分开筛选，避免被一个不匹配的成品包绑定尺度和风格。

1. 优先确认人工制作、CC0或许可清晰免费木构件；当前VVayToyek亭台只处于候选状态。得到原文件后先检查是否能独立提取柱梁，不默认拆网格或重建几何。
2. 帷幕必须有可验证的布面UV、可用法线和近景材质输入；已下载3DAssets两GLB缺少这些，不能直接正式接入。重新筛选有UV的人工作品，或把针对原模型的UV适配单列为独立候选任务；当前不搭建大规模自动建模管线。
3. 所有原始文件保留，单位、轴向、材质槽与派生操作逐项记录。用户不需个人手工建模；不把付费委托、生成服务、账户注册或新软件安装作为默认关键路径。
4. 合适资源未取得时保留当前可运行版本，只缩小首个构件样本范围；不以纯色帷幕、放大屏风或增加Bloom/雾掩盖问题，不宣布正式美术完成。

## 3. 最小架构、通信与生命周期

| 项目 | 边界 |
|---|---|
| 所有权 | 接受资产后的Dev框架采用少量原生StaticMeshActor；若实际需要固定组合与参数化摆放，再使用一个只持有StaticMeshComponents的表现型Actor/BP，不为未用行为先建C++子类 |
| 通信 | 静态框架无需任何谜题通信，不绑定Director/Stage事件、不主动发现灯偶。将来确需环境状态表现才由现有StagePresentation→StageEnvironment显式引用驱动，不产生第二流程所有者 |
| 状态 | 固定编辑器配置；不保存进度、不复制网络、不承担谜题判定。没有动态材质实例、Timer或Tick的默认需求 |
| 生命周期 | 由当前World创建/销毁，OpenLevel重演重新建立配置；Construction只作幂等内容组装，不做下载、写文件、世界扫描或不可逆操作 |

本轮没有创建上述Actor/BP；这是下一构件样本的最小选型和禁区，而非已存在的运行类。

## 4. 空间与原合同

下一样本必须以真实资源bounds与现有DEV_BackScreen几何为起点，冻结PLACEMENT记录后才写地图。当前接收体9m×8m、X925正面、Z[-50,750]不是正式尺寸定稿；不为了资源省事缩放幕布、移动主灯或改POV。

框架/侧幕不能占用核心保护盒，不能压住第一幕目标、第二幕身形参考、第三幕杖尖地线及成林有效区域。框架碰撞、Visibility响应、阴影、间接/距离场影响均独立明确，不能用“无碰撞”推导“不遮挡”。幕后结构的视觉接缝必须合理，保持同机位的幕后原因和幕上结果。

只新增环境构件时冻结原33 Actor完整合同。旧CameraWall、低梁、台阶等测试设施仍在，不默认删除/移动/隐藏它们：隐藏可能改变阴影，保留碰撞又改变外观需要独立验证，不能在本步顺便处理。已知右侧屏风下部被台阶遮挡、偏暗仍是缺口，不能用未经测试的补光解决。

不决定院落、封闭礼堂或特定时代建筑完整风格，不因空剧院声音要求推断某种建筑。大型接收体向正式小剧场尺度的迁移会影响构图和投影，另列设计权衡，不自动实施。

## 5. 材质与灯光

新构件保持现有Deferred/r.Substrate=0标准Surface/Opaque/DefaultLit；木和布分属有界材质族，常量MI用于静态变体。不直接复用地板12×9平铺实例到柱梁/帷幕，不提前搭建万能Master。

颜色纹理正确sRGB，NormalDX线性/NormalMap，粗糙度/打包数据线性；实读UV0、贴图密度、材质槽和近中远采样。布面双面与透光要由真实几何及正反视线决定，不默认启用透明或Substrate；无WPO、布料模拟、RVT、MPC或逐帧调参需求。

主灯、两盏五态环境灯、曝光、阴影和相机全部保持当前值；本步不写孤立亮度数值。不用Emissive让帷幕假发光。GPU与显存预算仍需目标机测量，不用面数少或材质编译成功代替性能验收。

## 6. 下一可实施样本与文件边界

首个样本只接入一个确实通过来源、UV/材质与尺寸检查的木框构件，或一块确实合格的侧幕，二者不为赶进度同时扩项。开始实现前记录具体资产包、现有地图/文档白名单、备份和回退包；当前不预建空资产目录和新启动器。

允许测试方式：隔离来源→Dev资产审查→只读尺寸/UV/材质检查→冻结摆放→写独立Dev样本→固定POV与行走→原控制/三幕/声音回归→Win64 Development独立Cook/Stage/Pak+IoStore/Archive与实际启动。现有Start-StageWingsDev固定包是回退，不重建或覆盖。

需要验证材质、渲染或输入行为时使用本机UE5.8源码/反射和实际测试，不猜.uasset节点。UE导入不支持源格式时先记录首个因果错误与最小实验，不能安装不必要插件或修改全局安全/代理/渲染设置。
