# 单网格枝叶样本：现有成林算法兼容性审查

日期：2026-10-16。只读审核；唯一人类作者和负责人为用户，Codex 辅助。仅在工作区新增本文，不运行 UE、不改 D 盘、不读取或哈希受限许可登记。

## 结论

可以把“闭合木干＋少量有厚度的柳叶形叶片”作为**独立 Dev 候选**；两个材质槽可以继续使用现有 Forest Actor，无需新增 C++、Tick、输入或流程阶段。但这不是“换一个更宽模型就获得更大树冠”的系统，以下三个数学限制必须先看清：

1. `DiameterWorld` 控制的是**整个网格包围盒**的两个横截面宽度，不是单独的木干直径。扩大源叶簇的 X/Y bounds 会被运行时缩放抵消，木干反而相对变细。
2. 所有 15 枝都使用同一网格，根枝和中段也会出现同样叶片；当前没有按枝选择木干/叶簇的网格变体。
3. 一枝刚可见时 X/Y 已具有完整直径，只有 Z 随生长进度拉长。叶片会先压成薄片，再沿枝长展开，不能把它描述成独立萌叶动画。

建议先固定原布局/直径/时序，只制作一款极简双槽枝叶候选，实际验证上述限制后，再单独比较一个增粗布局。不要同时重制布局、加纹理、加风摆、调曝光并据此宣称叶片方案成功。

## 根点、尖端与包围盒：具体会发生什么

现算法令 `C=(Min+Max)/2`、`E=Max-Min`，对每枝使用：

```text
Scale = (DiameterWorld/E.X, DiameterWorld/E.Y, BranchLength/E.Z)
Origin = (StartWorld+EndWorld)/2 - Rotation * (C*Scale)
```

因此每次实际对齐的是网格局部 `(C.X,C.Y,Min.Z)` 和 `(C.X,C.Y,Max.Z)`，并非查询真正木干的根顶点、叶柄或骨骼。代码的数值门可以正确通过，但源木干若不在这条轴上，视觉上仍可能与 A 接触点错开。

最小源约束：

- 保持原 Z `[-50,+50]cm`；叶片不越过端面，底部先留一小段无叶木干，顶部保留真正轴端，不以悬出的叶尖成为 `Max.Z`。
- X/Y bounds 中心保持 `(0,0)`，真实木干根/尖仍位于 `(0,0,-50)` / `(0,0,+50)`。成对、交错叶片可以保持中心，但必须测实际最终 bounds；不能只说“枢轴在原点”就认为根点安全。
- 叶片厚度、叶柄与木干必须是可渲染的有限实体，不用背面单片的默认剔除碰运气。可保留多个闭合壳体，但叶柄接点须真实相交或连续，避免近景漂浮。
- 不均匀 runtime XY 缩放必然存在：算法把两个总宽都归一化成相同 `DiameterWorld`。源叶长宽比例和折面在 UE 中的样子需按实际变换看，不应以 Blender 单件预览替代。

若叶簇把 ExtentX 放大到原来的2倍，而 Diameter 不变，源木干 X 截面就缩为原来的1/2；叶簇最终包络仍只等于原 Diameter。叶片只能在现有窄包络里增加覆盖，不能凭加宽源几何自动扩冠。

## 投影、裁切与布局的失效边界

- `Lift` 将布局端点逆投影到真实 A 的光线深度，根点由真实接触和 Token 决定。没有必要改接触、Staff、地线 Z70 或谜题参数。
- 显示前会投影**整个 bounds 的八个角**，任一角不在幕内就返回 `OutsideScreen`；Forest Actor 随后清除整场资源，而不是只裁掉越界的一片叶。
- 新 bounds 即使仍居中，改变 Z/横向比例也会改变旋转后的八角投影。不能仅由 Start/End 仍在幕内推定叶片安全。
- 叶片壳体在包围盒内，不代表真实影子会好看、无自遮挡或枝叶不糊成团；八角包络是保守几何门，不是阴影像素审查。
- 改直径时，子枝 `DiameterWorld <= Parent.DiameterWorld` 必须成立；不能只把末端枝调成比父枝更大的“树冠”。整体同倍率增粗可保持这个不等式，但根附近和边缘八角仍需重采样。
- 改生长顺序时，父索引必须在子之前，子起点等于父终点，`child.GrowthBegin >= parent.GrowthEnd`，且 `0<=begin<end<=1`。不能为了层次随机排序数组或提前出叶。
- “父直径不小于子直径”只是整个 bounds 的条件，不证明真实渐细木干的父尖和子根横截面匹配；仍须看交接处是否有粗疙瘩或间隙。

## 材质与组件边界

当前 C++ 对每个组件先 `SetStaticMesh(SessionMesh)`，只在 `BranchMaterial` 非空时 `SetMaterial(0, BranchMaterial)`。所以新网格应明确：

| 槽 | 含义 | 首样本接法 |
|---|---|---|
| 0 | 木干 | 保持现有 Wood MI，允许现有 BranchMaterial 只覆盖槽0 |
| 1 | 实体叶片 | 网格自身绑定有限的叶色材质；冷读和真实动态组件均核对未被槽0覆盖 |

首样本叶材质使用 Surface / Opaque / DefaultLit / 单面，配合闭合薄实体；Metallic=0、粗糙表面、不发光。只有一个简单直接父材质，确需颜色比较才留一个叶色参数，不建立通用材质库、静态开关、MPC、WPO、风系统或透明叠层。

颜色为作者审美候选，不把“柳叶形”叫作植物学桃树或《山海经》原貌。原生 Opaque 主灯影子不会因叶片粉红而变粉红；幕上美术收益主要来自轮廓、疏密和节奏。不可用 Emissive 把后台叶片做亮来冒充林影改善。

两个材质槽在15组件上增加分区成本，不能声称仍是原先单槽 draw call。没有新大纹理、Mask/Translucent、WPO 或动态实例即可控制复杂度；实际 GPU 和录屏依旧待目标机测量，不报猜测帧数。

## 最小首测：一款候选、两组对照

### A. 仅换网格/增加槽1，原15枝布局全部不动

1. 源候选只用少量交错的窄叶；首批建议2–4片作为比较起点，而不是预先认定正式数量。暂不做巨大球形叶冠、花瓣、风摆和多网格选择。
2. 本地几何检查：真实 bounds/轴端、闭合壳体、非退化面/UV、材质归属、叶柄接触、源/导入法线与导出轴向。
3. Native 新资产与独立数据 BP：只换新 mesh 与新槽1材质；原15 definitions、原舞台时长、原主灯/曝光保留，原 asset/BP 不覆写。
4. 读取真实接触快照，针对0、1、每个枝 `GrowthBegin` 前后、局部 Portion `1%/10%/50%/100%` 调原几何函数。所有样本须 Valid；根/尖数学端点、ActualRoot/ShadowRoot/Token一致，原 Start/End 不变。
5. 实际动态组件核对：全15件引用新 mesh，槽0为木、槽1为叶，无碰撞、同一主灯真实投影；不直接换运行中的组件 mesh。
6. 真实 PIE 在原同一机位看接触前、首次冒出、半长、完成；至少补一个幕后斜视枝叶近景。重点否决“根点已先冒叶”“完整横宽突然弹出”“被非均匀拉成针/宽片”“重复叶片机械整齐”。

### B. A确实成立后，才比较单独的直径候选

复制候选 BP，先只试一个统一直径倍率（例如与1倍对照的2倍是实验候选，不是最终取值），布局端点/顺序/时序仍固定。逐枝八角/根附近/边缘/完整生长采样通过后再看实际画面；不要把“叶子变宽”与“森林改布局”同时引入而失去比较依据。

如果统一增粗破坏根部或画面，则再根据真实帧调整分枝直径与生长区间，遵守父子不等式。仍不应新增 HISM、Foliage、Niagara、第二盏成林投影灯或贴图林影替代真实因果。

## 什么算通过，什么还不能叫完成

候选的最低通过条件是：比当前细枝架更像有疏密的枝叶，不损害夸父/手杖轮廓；实际根点连续，无枝叶突然铺开、漂浮或越界整林消失；原三幕/接触/成林/重演不退化；同机位主灯 A/B 与近景均可解释真实几何投影。

仍不能由静帧或数值 Valid 推定：5–8分钟体验、玩家首玩理解、真实按键/相机手感、低画质/全部分辨率、GPU预算、Development/Shipping 包和录屏已完成。

当前不建议为了看起来“稳妥”退回无叶枝架作为最终艺术终态；也不建议在单网格算法上硬称实现了独立萌叶/植物生长。若首次实测证明压片生长在最终机位明显难看，应如实回报这个结构性限制，再选择有证据的最小呈现调整，不以更亮曝光或截图角度掩盖。

本轮使用 Blueprint 架构技能限定会话/组件归属与只配数据的接入；Materials 技能使叶片保持有限 Opaque 表面，不为一个候选新建透明/风摆/通用材质框架。未生成/导入新模型，未运行 UE；本文不是候选成品或美术验收。
