# 《灯影山海》剧院声音 Dev：实施边界与验收计划

日期：2026-10-10。本项目为用户单人制作；Codex 直接负责本轮技术实现、工具执行与技术验收，不新增队友分工，不依赖 WorkBuddy。用户保留作品作者身份并完成最终设备听感与游玩体验确认。

## 1. 玩家可见／可听结果

目标是修正“源声音过弱、行走缺少脚步、空间缺乏空荡剧院感”，不是增加玩法、扩大地图或改成真实建筑声学模拟。

玩家在同一主地图中正常行走时，实际步行位移触发 A/B 交替脚步；停止行走不因按住键、镜头变化或后台计时继续敲步。Holding 的有限节奏、前两幕 Resolve、真实杖尖接触、成林枝叶声仍跟随已有事实事件。

增加克制的剧院式尾音，短击声结束后可以留下有限、可测的衰减；避免把直接 attack、通关提示和枝叶声全部淹没在长混响中。新声音候选的材料与人耳效果尚未签收。

## 2. 不变的范围

- 仍是一个连续小剧场、一个主地图；“大型空荡剧院感”是声音表现目标，不新增大型可探索剧院、房间或关卡。
- 不改 E/A/D/R、灯／偶速度、谜题目标与容差、15 Hz 判定、保持时间、三幕串联、中文 UI 或菜单规则。
- 不改变真实阴影与逻辑判定分离，也不改变 A 端／Z70／落杖／接触／成林的空间因果。
- 不新增脚步按键、声学解谜、敌人听觉、玩家音量必须达标才能通关等规则；静音时已有视觉反馈仍应完整可用。
- 本轮使用七个新免费声音资产，保留旧声音、旧地图／包与旧启动入口。无付费资产、非必要插件或引擎源码修改。

## 3. 脚步触发的最小架构

脚步由角色实际移动更新事件驱动，读取实际地面移动的水平位移并累计距离，不以输入意图证明移动，不新增独立 Actor Tick、按帧世界扫描或脚步 Timer。

候选间距为 **150 cm**。当前满速约 **360 cm/s** 时，理论为 `360 / 150 ≈ 2.4 步/秒`；它是位移派生结果，不是硬编码 2.4 Hz 声音时钟。慢行、阻挡或停止会自然减少／停止触发。
A/B 只是交替变体，不宣称原录音来自真实左／右脚或已确认木地板。

复位、重演、新世界生命周期须清理累计位移与旧声音归属，避免将复位／瞬移当成连续行走或将旧世界声音带到新世界；以动态验证为准，不在本计划中冒称已经通过。

原五声仍由现有演出事实驱动：Holding 进入／退出只控制循环开始／停止，不能随 15 Hz fraction 更新反复重启；前两幕 Resolve 各一次；第三幕接触声只在已接受接触后发出；枝叶只在真实成林终态成立后开始。音频表现不反向决定 Puzzle Director 或演出状态。

## 4. 原生混响候选

使用 UE 已有的 **NativePlate** 路线，不添加付费声效插件，不靠录入新建筑或修改引擎实现空间感。

Dev 候选参数为 **2.4 s** 衰减感与 **35 ms** 预延迟。它们是算法混响的演出参数，不是按戏台几何求得的真实 RT60，也不是对“真实大型剧院体积／材质”的测量；不以 NativePlate 名称宣称声学真实性。

原生 effect／submix 负责声音表现，音频 Actor 与实际移动／舞台状态事件负责提交声音。直接声与尾音分工须保证 attack 和提示可辨；具体总线发送、运行增益和资源配置由主实现者保留文件与回退记录。

五个新源文件相对旧 Dev WAV 提升约 **12–16 dB**，sample peak 候选上限为 Wind .20、Holding .28、Resolve .48、Contact .64、Leaves .16，脚步 A/B 约 .45。只做本轮源文件与游戏内受控增益，不无限加大，不更改系统主音量。
**单声源没有削波，不代表实际混音叠加后一定安全；实际混音必须另测。**

## 5. Windows 输出端点的事实边界

本轮曾有一次只读查询返回 Windows 输出端点 **mute=true、master=0**。这只描述查询当刻，不代表该状态持续、所有应用输出都相同或它是唯一原因；不能用端点结果替代游戏实际混音检查。

Codex 不解除系统静音、不调整 Windows 主音量、不更改默认输出设备。用户自行通过 Windows 的音量／输出设置解除静音，并缓慢调到舒适音量，不建议为验证直接拉满。
本方案仍须验证游戏自身的新 source、提交事件与实际主混音；系统端点需要用户自主操作，不能通过伪造 WAV、改静音门限或把游戏混音“非零”称作用户已经听到来绕过。

## 6. 验证方案与完成边界

本计划不代写动态结果；实际结果、执行命令、hash、失败记录与包验证由主验收者写入本轮 Validation。当前实际 Windows 混音、设备出声与人耳听感均为 **pending**。

需要保留以下互补证据：

1. 原源码／配置／资产与旧包基线；七个新增 WAV 的来源、许可、hash 和处理链。
2. 实际步行事件：位移触发、A/B 交替、阻挡／停止／复位不连发，没有脚步 Tick 时钟。
3. 原五声事实事件与生命周期：Holding 开停、前两幕 Resolve 次数、接触／成林条件、复位／重演、完整静音流程。
4. 新可见 Dev 与 Windows 包的实际主混音 WAV，不采麦克风或桌面回环、不注入合成替代录音。
5. 明确对齐的 walk-dry／walk-room 短声结束后窗口：room 尾音应相对 dry 有显著数值提升，并超过明确的绝对 RMS 底线；窗口与标准由主验收者定义并记录。
6. mute-start 窗口全零，或在预先记录的不超过一个 PCM16 LSB 的量化噪声门限内；如超出则报告原值，不临时放松门限。
7. 完整 PCM16 / 48 kHz / stereo RIFF/data、峰值、RMS、非零样本、正负满幅 rail、SHA256；足声窗口有声且无削波。相对旧约 -51 dBFS 的混音 RMS 指标可作数值对照，但不同流程长度／内容不是校准的主观响度试验。
8. 用户在实际设备、舒适音量下确认能听清脚步与关键提示，空间尾音合适；这是人耳确认，不由源 sample peak、组件 is_playing 或非零 WAV 代签。

`Check-TheatreMix.py` 只分析既有实际 WAV，支持实际文件路径与明确定义的 WAV-sample 秒窗口；没有完整尾音／静音／足声窗口时只报告局部覆盖，不误标全通过。游戏世界时间与音频 sample 时间若无共同 t0，不能直接当作精确因果时刻。

所有失败记录保留，新的运行使用 fresh 审计目录，不覆盖旧失败 WAV、报告或旧包。最终启动文件位置由主验收者在交付时确认，不在本文编造已可用入口。
