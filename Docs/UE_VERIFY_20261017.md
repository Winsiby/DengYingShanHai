### 7.1 夸父 BP 装配机制——审查意见第三节"关键疑点"的初步解除


## 8. 第三轮核验（v4，响应《UE内部核验审查意见_第二轮更新.md》§5.4/§6.1）

### 8.1 "接触 opt-in 与授权参数"的澄清（§5.4 的答案）

完整通读 `DYStagePresentation.h`（301 行）后确认：**该类上不存在独立的"接触 opt-in 数值"或"授权参数"属性**。授权是运行时双校验机制，不是可配置数值：

1. **Token 校验**：`TryAcceptStaffContact/BeginForestPresentation/SetForestNormalizedGrowth/SubmitForestFinaleCompletion` 全部要求当前有效的 Director Resolve Token（`IsStaffPresentationTokenCurrent`；"Repeated/late old tokens must not clear a new cue"）。
2. **实际几何校验**：`TryAcceptStaffContact` 注释明示"Reads actual A-end geometry; a caller cannot self-report a successful location"（`IsContactSceneUnchanged`）；`SubmitForestFinaleCompletion` 注释明示"native checks actual contact and full live branch geometry. A resolved Token alone never authorizes experience completion"。

可配置项**已全部读取完毕**（编辑器加载态实例 introspect，`UE_VERIFY_V3.json`）：

| 属性 | 实例值 |
|---|---|
| `bEnableStaffContactPresentation` | true |
| `bEnableFiveStateDevEnvironment` | true |
| `bEnablePlayerAlignmentFeedback` | true |
| `ForestPresentationActor` | → 主图森林实例 |
| `StaffProjectionScreen` | → `StaticMeshActor_1` |
| `PuzzleDirector` | → `DYPuzzleDirector_1` |
| `StageEnvironment` | → `BP_DYStageEnvironment_C_0` |
| `NarrativeGroundLine` | → `TargetPoint_1`（位于杖落点区 (925, 0, 70)，与 StaticMeshActor_14 同位，符合头文件"须在发射面朝向的接收面上、无隐式地面 Z"的约束说明） |

**对审查意见 §5.4 的正面回答**："按真实成员名读取授权参数"的结果是——授权在设计上不由参数控制，而由 Token+几何双校验的 C++ 运行时链控制（证据：`DYStagePresentation.h` 第 47-52、66-71 行函数契约注释）。因此该核验项以"配置面全部读取 + 授权机制静态确认"收口；运行时行为需 PIE。
