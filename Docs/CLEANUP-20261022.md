## 4. 结论与规则

1. 打包流水线每轮会在 `Saved/` 生成 `<Build>-Cook` 与 `<Build>-Stage` 两份中间产物，体积约为成品的 1.3 倍；成品归档到 `Builds/` 后，这两份**每轮都可以立刻删**。
2. 长期只保留「当前包 + 最近两包 + 一个 Development 包」，其余旧包删除不影响任何文档（`Docs/` 里记录的是 hash 与字节数，不是包体）。
3. 删除审计目录前，先抽取 ≤512 KB 的文本证据到 `Saved/EvidenceArchive-<日期>/`，二进制截图与旧包一并释放。
4. `Saved/Audit-2026-10-20-V21` 是交付证据库，**不要**用批量脚本碰它；单个试验目录（`Audit-2026-10-22-*`）可以按轮次清理。
5. `Saved/` 与 `Builds/` 均不受 git 跟踪（`git ls-files Saved Builds` 为 0 条），清理不会产生受跟踪文件的删除，也不需要提交。
