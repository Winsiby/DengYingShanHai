# ENVIRONMENT & NARRATIVE SPEC｜剧场环境与最小叙事规格

## 1. 目标与范围

本文件解决两个问题：

1. 让《灯影山海》看起来是一座完整的小型影戏剧场，而不是“幕布、灯和皮影悬浮在黑盒里”的技术测试场景；
2. 用最少的文字和资产回答“戏台为什么沉寂、玩家为什么操作、为什么必须演到弃杖化林”。

范围保持不变：

- 仍然只有 `L_DY_Main` 一个主地图；
- 仍然只有一个戏台、三次核心互动和一个高潮；
- 新增的是同一戏台周围的空间层次与表现状态，不是第二关卡；
- 不增加环境解谜、调查、收集、NPC、对话树或自由探索任务；
- 场景是受中国皮影演出结构启发的虚构小剧场，不宣称复原特定时代、地域或流派。

一句话空间策略：

> 不增加可玩地图的数量，而增加同一戏台的前后纵深、台翼层次、垂直结构、状态变化和文化含义。

## 2. 推荐故事背景

### 2.1 正式梗概

在山野边缘，有一座久未开演的小型影戏台。最后留下的一出戏名为《逐日》，但演出停在夸父尚未落杖的时刻：灯偏离轨道，皮影留在幕后，锣鼓与唱腔也随之沉寂。

玩家作为来到戏台的“复演者”，不负责修复文物，也没有拯救世界的任务。玩家只需要重新建立灯、偶与幕之间的关系：引日归位，使夸父重新逐光，并亲手完成最后的落杖。杖尖触幕之处生出邓林，这出未完成的戏才获得结尾。

演出结束后，戏台仍是一座小戏台；但风穿过幕布上的林影，说明神话只要再次被人操作、观看和讲述，就仍然活着。

### 2.2 玩家身份

玩家统一称为“复演者”。当前版本不提供姓名、家族、师徒、职业或复杂身世。

玩家动机只需要一句话成立：

> 这里有一出没有演完的戏，而玩家可以把它演完。

禁止为解释玩家身份新增：

- 戏班 NPC 或灵魂角色；
- 失踪亲人、家族传承或师徒任务；
- 可阅读的长篇日记与文献；
- 多段配音独白；
- “拯救世界”或“修复历史真相”的宏大任务。

### 2.3 开场与结尾文字

> 2026-10-01 文案定稿：本节采用“原典短引 + 团队引导语”的双层结构。若下方早期占位文案仍出现在旧导出版本中，以本段为准。

开场第一张信息卡（原典，保留繁体字形）：

> “夸父與日逐走，入日。”  
> ——《山海經·海外北經》

开场第二张信息卡（团队创作）：

> 把这出未完的《逐日》，重新演完。

两张卡总时长约 4–7 秒并允许跳过。原典与团队创作文案必须分层显示；若增加简体释义，应明确标注“今译/释义”。开场不展示完整段落，避免提前泄露“道渴而死”和“弃杖化林”。

结尾在玩家完成第三次互动并直接触发“杖落成林”后回收原典：

> “棄其杖，化為鄧林。”  
> ——《山海經·海外北經》

> 灯影未息，故事仍在人手中。  
> ——团队创作余韵句

原典文字依据中国哲学书电子化计划核对；文化、字体、材质、音频和开放藏品的来源与授权边界见 `Docs/ASSET_SOURCES.md`。

以下两句为早期气氛占位文案，已由上方“原典短引 + 团队引导语”定稿替代：

```text
灯熄以后，影停在了逐日途中。
把这出未完的戏，重新演完。
```

三段之间只显示短题签：

```text
引日启幕
逐光成形
杖落成林
```

结尾可分开显示原典与作者创作表达：

```text
> （早期简体占位；最终屏显采用上方繁体原典。）
——《山海经·海外北经》

灯影未息，故事仍在人手中。
——团队创作表达
```

原典、作者创作和第三方材料必须在排版及片尾来源中清楚区分。

## 3. 单地图空间结构

### 3.1 推荐灰盒尺度

以下数值只作为第三人称灰盒起点，不是历史戏台复原尺寸：

- 整体可见剧场：约 `14–18 m` 宽、`10–14 m` 深、`5–7 m` 高；
- 核心幕布：约 `5–6 m` 宽、`3–3.5 m` 高；
- 幕后操作区：约 `4–5 m` 深；
- 简化台前观演区：约 `4–6 m` 深；
- 左右台翼：各约 `1.5–2.5 m`；
- 入场短廊：只承担约 `10–20 秒`进入与视觉引导。

尺寸必须根据角色胶囊、Spring Arm、操纵机位、幕布构图和目标电脑表现复测，不因“看起来宏大”而拉长无意义步行。

### 3.2 俯视布局

```text
                         不可探索的远山 / 夜色 / 风
┌────────────────────────────────────────────────┐
│                简化台前观演区                   │
│       少量长凳       正面全景机位       侧幔帐    │
├────────────────── 半透明幕布 ───────────────────┤
│ 左台翼/锣鼓角    皮影轨道与操杆    右台翼/道具架 │
│                                                │
│ 皮影挂架          主灯轨道          纹样/支架     │
│                                                │
│             玩家主要幕后操作区域                │
├────────────────────────────────────────────────┤
│       入场短廊 / 《逐日》题签 / 未完演出线索      │
└────────────────────────────────────────────────┘
```

从观众侧到幕后侧的因果顺序固定为：

```text
台前观演区 → 幕布 → 皮影/操杆 → 主灯 → 玩家幕后通道
```

### 3.3 五个空间区

| 区域 | 玩家是否自由进入 | 作用 | 最小资产 |
|---|---|---|---|
| 入场短廊 | 是 | 建立沉寂、引导主灯、给出最小背景 | 题签、木构、幕角、冷光、一个明确视觉出口 |
| 幕后操作区 | 是，核心活动区 | 承载三次交互和双空间观察 | 主灯、轨道、皮影、操杆、幕布、操作台 |
| 左右台翼 | 只允许有限靠近 | 形成横向层次，放置乐器/道具/挂架 | 锣鼓角、皮影挂架、纹样架、幔帐 |
| 台前观演区 | 主要由镜头展示 | 提供正面神话全景和结尾观看位置 | 少量长凳、立柱、侧幔、标题区域 |
| 外部远景 | 不可进入 | 扩大世界感，回应山海与风 | 远山卡片/平面、纸窗、雾层、低成本树影 |

边界优先由幔帐、道具架、暗部、木栏和构图自然形成；碰撞只负责安全，不用大面积醒目的空气墙提醒玩家“这里不能走”。

## 4. 环境叙事

### 4.1 不用文字也要成立的线索

开场环境至少让玩家推断出：

- 这里曾经用于演出；
- 《逐日》停在未完成状态；
- 主灯和夸父皮影的位置不正确；
- 手杖是终章关键物件；
- 锣鼓和幕布都在等待重新启动。

推荐线索：

- 入场处的《逐日》题签或残缺日轮纹样；
- 皮影挂架中夸父位置留下的空槽或磨损；
- 主灯轨道上的使用痕迹；
- 持杖/落杖姿态草图式纹样，但不直接给出谜题答案；
- 未被敲响的鼓、锣和木击器；
- 幕布边缘尚未展开的林纹；
- 纸窗或门缝外的远山与微风。

不建议使用“积满厚灰、破败坍塌、鬼影观众”等强烈恐怖符号。环境应读作“久未开演、仍可复演”，而不是闹鬼废墟。

### 4.2 叙事信息三层

| 层级 | 呈现 | 必须程度 |
|---|---|---|
| 第一层：动作与环境 | 灯、偶、幕、声音和场景状态直接说明发生了什么 | 必须；不看文字也能理解核心因果 |
| 第二层：短题签 | 开场两句、三段名称、结尾原典与原创表达 | 必须但极少；不打断操作 |
| 第三层：完整说明 | 创作说明、来源、改编边界、技术与许可 | 放菜单/片尾/参赛材料，不塞进核心流程 |

## 5. 环境随演出的五个状态

环境不是新谜题，只响应现有流程事件。

| 表现状态 | 进入条件 | 灯光/色彩 | 空间变化 | 声音变化 |
|---|---|---|---|---|
| Dormant 沉寂 | 开场 | 冷灰环境底光；主灯仅有明确微弱焦点 | 台前、台翼大多隐藏在暗部；幕布残缺 | 微风、木构、远处环境 |
| SunAwakened 引日 | P01 Resolve | 幕布中心出现第一层暖金；曝光基线不变 | 题签/一侧纹样被轻微照亮 | 第一声木击与单层鼓点 |
| ChaseAwakened 逐光 | P02 Resolve | 暖色范围扩到台翼，但主灯仍是视觉核心 | 皮影挂架、锣鼓角、前排长凳获得层次 | 脚步、呼吸和更密鼓点 |
| FinaleReady 落杖前 | P03 Holding/Resolve | 对比收紧，日轮和杖尖成为焦点 | 外围不过早完全亮起；风纹/林纹开始响应 | 风、低吟与鼓点聚拢 |
| ForestComplete 成林 | 杖尖接触/Finale | 暖金、朱红、墨色完成；次要环境只为高潮服务 | 林影从幕布越到立柱、地面或梁架；台前完整显现 | 枝干、叶片、完整吟唱与锣鼓层 |

每个状态都要用固定机位截图对比。若两个相邻状态无法在不看 UI 的情况下区分，先调整焦点层级、材质参数和局部灯范围，不增加更多特效。

## 6. 灯光与曝光策略

### 6.1 层级

场景灯光分三类：

1. **关键主灯**：玩家操纵的 Movable 灯，负责幕布实时阴影与“日”的玩法；
2. **环境底光**：保证入场、通道和幕后操作可读，不与主灯争抢；
3. **演出强调灯**：随 Stage Presentation 状态开启或变化，照亮题签、台翼、锣鼓角和观演区。

环境灯永远不能破坏主灯投影的轮廓和对比。高潮也不能用全场泛白代替构图。

### 6.2 技术假设

- 继续使用 Deferred Renderer、Movable 主灯和优先测试的 Virtual Shadow Maps；
- 环境几何以 Static Mobility 为默认，只有确实需要动画的幕布、幔帐或表现物使用合适的可动性；
- 灰盒调灯先使用 Manual Exposure；最终互动阶段保持固定或窄范围受控曝光；
- 环境局部灯使用与实际灯具相符的 Point/Spot/Rect 类型和物理单位；
- Attenuation Radius 只限制影响范围，不能用来补亮整个剧场；
- Source Radius/Width/Height 决定阴影柔度和反射形状，应服务幕布轮廓而非随意调节；
- Lumen 可承担环境反弹，但所有状态仍需在关闭非关键 GI 增强后保持可读；
- 单场景、少量关键灯的基线不依赖 MegaLights；只有目标机对照测量后才决定是否采用。

### 6.3 状态变化规则

- 先锁曝光，再调灯光状态；禁止通过自动曝光把 Dormant 和 Finale 都拉回同一亮度；
- 环境苏醒优先改变局部灯、材质参数和可见范围，不让每个状态都新增灯；
- 使用最小有效 Attenuation Radius，避免多盏局部灯在幕布像素上大量重叠；
- 远景平面和非关键装饰默认不投动态阴影；
- 只有主灯、夸父、手杖和必要操杆的关键阴影属于不可牺牲项。

## 7. 镜头与玩家路径

### 7.1 四个镜头任务

| 镜头 | 所有者 | 任务 |
|---|---|---|
| Explore | Pawn Camera + Spring Arm | 用短路径介绍入场、台翼和幕后纵深，保持玩家控制 |
| Manipulate | `BP_DYStageCameraRig` | 幕后三分之四同框，证明灯/偶与幕上结果的实时因果 |
| Finale Cause Shot | Sequencer Cine Camera | 不切镜展示最终影形、杖尖接触和林影首帧 |
| Audience Reveal | Sequencer Cine Camera | 在因果已经证明后转到台前，展示完整山海画面，再揭示幕后来源 |

本地 PlayerController 仍是 View Target 切换入口。Camera Cut Track 只在短过渡和 Finale 拥有最终 POV；完成、跳过、中断和 Sequence 销毁都走统一恢复。

### 7.2 推荐玩家路径

```text
入场短廊
→ 看见未完成幕布与唯一微亮主灯
→ 进入幕后核心区
→ 三次互动主要在同一区域完成
→ Finale 镜头转到台前观看完整结果
→ 结束界面提供重新体验/退出
```

不要求玩家为了“地图更大”反复走到台前、绕回幕后。台前主要是镜头空间，不新增导航任务。

### 7.3 构图验收

- 入场第一帧不直接暴露全部空间，但主灯和幕布方向明确；
- Explore 相机在短廊、低梁、台翼转角不穿模、不急剧回缩；
- Manipulate 镜头仍满足幕后/幕上同框规格；
- Audience Reveal 不把画面拍成与实时操作无关的预渲染宣传片；
- 常用画面比例下，题签、幕布、字幕和核心影形都在安全区；
- 先确定机位、主体、遮挡和基础 FOV，再加 Lag、Shake、景深与后处理。

## 8. Blueprint 所有权与通信

### 8.1 `BP_DYStageEnvironment`

新增一个放置在 `L_DY_Main` 的表现型 Blueprint Actor，用于收拢同一剧场的状态变化。它不是新玩法系统。

职责：

- 持有环境强调灯、需要变化的材质实例、台翼/题签/幔帐等表现引用；
- 在 BeginPlay 创建并缓存需要的动态材质实例；
- 接收 Stage Presentation 的显式状态调用并应用 Dormant、SunAwakened、ChaseAwakened、FinaleReady、ForestComplete；
- 提供幂等的状态应用和最终状态入口；
- 在无 Tick 的前提下用 Timeline、Sequencer、材质动画或一次性过渡完成表现；
- 缺失非关键引用时记录错误并跳过该项，不阻塞谜题和结束界面。

不负责：

- 查询或修改 Puzzle Director；
- 发现灯具、皮影或其他 Actor；
- 判定谜题成功；
- 保存跨地图状态；
- 操纵 PlayerController 或决定相机；
- 承载环境解谜。

Construction Script 只做可重复、编辑器安全的预览/组装；运行时动态材质、委托和过渡在 BeginPlay 或显式运行函数中初始化。

### 8.2 通信

```text
ADYPuzzleDirector
    └─ 状态事件 → BP_DYStagePresentation
                         ├─ 直接引用 → BP_DYStageEnvironment
                         ├─ 直接引用 → BP_DYStageCameraRig
                         ├─ 直接引用 → BP_DYForestGrowthActor
                         └─ 本地 Controller → View Target / 输入交接
```

选择直接引用的原因：主地图中每类对象都只有一个稳定实例，关系是一对一。这里不建立 Subsystem、全局消息总线，也不使用 `Get All Actors of Class` 进行依赖注入。

Stage Environment 不绑定 Director，避免出现两个流程所有者。Stage Presentation 在 Director 状态已经确认后才调用环境表现。

## 9. 美术与性能边界

### 9.1 必须完成的环境资产

- 连续小剧场壳体：短廊、幕后、台翼、幕布框架、简化台前；
- 皮影挂架、灯轨、操杆架与锣鼓角；
- 少量长凳、立柱、幔帐和上方木梁；
- 一套不可探索的远山/夜色/风景层；
- 《逐日》题签、日轮/山纹/林纹等环境叙事图形。

### 9.2 低成本实现

- 远山、树影和窗外层优先使用低成本平面、卡片、雾和简单材质，不建立可探索地形；
- 台前长凳只做少量模块复用，不制作完整观众席；
- 台翼道具保持少而清楚，不填满杂物；
- 大多数装饰不需要碰撞和动态阴影；
- 不为环境建立 World Partition、Level Streaming、HLOD 管线或昼夜系统；
- 不允许环境资产影响 5–8 分钟主流程和 Windows 打包稳定性。

### 9.3 止损顺序

环境制作延期时按以下顺序保留：

1. 幕布、主灯、夸父、手杖和幕后核心结构；
2. 连续剧场壳体和三分之四操纵机位；
3. 台翼、锣鼓角与皮影挂架；
4. 简化台前和上方木梁；
5. 远山、窗外层、次要装饰和观众剪影。

不得因环境延期删除第三段直接因果、真实主灯阴影或调试/打包验证。

## 10. 责任分工

### 项目负责人

- 灰盒尺度、玩家路径、碰撞与可玩边界；
- `BP_DYStageEnvironment`、Stage Presentation 接线与状态过渡；
- Explore/Manipulate/Finale/Audience Reveal 相机；
- 环境灯光、曝光、性能和打包验证；
- 短字幕、状态触发与文化边界终审。

### 同一作者的资产与视频任务

- 剧场壳体、台翼、挂架、长凳、木梁、远景和叙事纹样资产；
- 原创过程稿、尺寸/枢轴/材质槽交付；
- 宣传视频中的环境建立、状态对照和高潮镜头剪辑；
- 第三方参考、纹样、字体与素材来源记录。

## 11. 验收清单

### 空间

- [ ] 玩家在进入后 20 秒内明确看到主灯、幕布方向和可达路径；
- [ ] 场景读作完整小剧场，而不是黑盒中的三个独立资产；
- [ ] 入场、幕后、台翼、台前和远景属于一个连续空间；
- [ ] 没有第二地图、环境任务或无意义长距离步行；
- [ ] 角色、Spring Arm 和舞台相机在短廊/台翼不穿模或严重弹跳。

### 叙事

- [ ] 不看长文本也能理解“久未开演—未完逐日—玩家复演”；
- [ ] 玩家能说明自己是在完成一出未完的戏，而不是修复文物或探索遗迹；
- [ ] 开场文字不超过两句，三段只使用短题签；
- [ ] 原典引用和作者创作文字有明确区分；
- [ ] 没有新增 NPC、复杂身世、收集品和支线。

### 状态与灯光

- [ ] Dormant、SunAwakened、ChaseAwakened、FinaleReady、ForestComplete 能用同机位截图区分；
- [ ] 环境灯没有削弱主灯在幕布上的关键阴影；
- [ ] 固定/受控曝光下，开场仍暗但可走，高潮明亮但不泛白；
- [ ] 降低非关键画质后，主灯、影形和玩家路径仍清楚；
- [ ] `BP_DYStageEnvironment` 不 Tick 扫描世界、不读取 Director、不决定流程。

### 展示与性能

- [ ] 入场、操纵双空间、Finale 因果和台前全景各有稳定可复现机位；
- [ ] 一段无切镜画面可以证明“幕后操作—幕上变化”；
- [ ] 一段无切镜画面可以证明“落杖—接触—成林”；
