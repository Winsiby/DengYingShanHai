# DEVELOPMENT PLAN｜里程碑制开发计划

## 1. 计划原则

本项目不绑定固定天数，也不按“第几天必须完成什么”安排工作。开发周期根据赛事截止时间、作者可投入时间和实际验证结果调整，但作品范围保持不变：

- 一个连续小型影戏剧场主地图：入场短廊、幕后、台翼、简化台前和不可探索远景；
- 三次复用同一框架的核心互动；
- 一个由玩家最终影形触发的高潮结尾；
- 5–8 分钟完整体验；
- Windows 可运行 Demo；
- 可追溯的技术、文化、美术、许可和 AI 使用证据。

所有工作按里程碑推进。只有当前里程碑的退出条件全部满足，才能进入下一个里程碑。延长周期用于提高完成度、表现和验证质量，不自动授权扩场景、扩玩法或扩系统。

## 2. 单人制作责任边界

用户本人是唯一人类作者与项目负责人，负责技术、策划、免费合规资产筛选与适配、灯光、声音、动画、视频、许可及最终提交。Codex 是实现与核查辅助工具，不作为制作成员；WorkBuddy 仅在用户另行指定的任务中辅助。

不预设作者具备手工建模、绘画或表演录制能力。优先复用已验证组件、采用许可清晰的免费资源及可重复适配流程。全部 P0 工作串行收敛，不安排技术与美术由不同成员同时交付。任务唯一负责人是用户，具体 AI 执行者按当轮授权记录。

单人制作不自动删减现有范围或降低成品质感；需降级、改参数或改演出节奏时仍先确认。完整规则见 `Docs/SOLO_PRODUCTION.md`。

## 3. 里程碑总览

| 里程碑 | 核心结果 | 允许进入下一阶段的条件 |
|---|---|---|
| M0 范围与环境锁定 | 文档、引擎、编译、版本管理和文化来源可追溯 | 环境检查通过，范围与原创边界确认 |
| M1 核心垂直切片 | “引日启幕”从输入到成功反馈完整可玩 | 编辑器和独立 Development 包均可完成 |

| M3 Alpha 可理解版本 | 引导、反馈、重置、占位演出和基础音频成立 | 首次玩家多数能独立完成，时长接近 5–8 分钟 |

| M5 Beta 性能与兼容 | 目标机性能、打包、Cook、连续通关稳定 | 无 P0，P1 有修复或降级决定 |
| M6 Release Candidate | Demo、视频、文档、许可与证据齐全 | 干净路径验证、三轮通关、提交件逐项打开 |
