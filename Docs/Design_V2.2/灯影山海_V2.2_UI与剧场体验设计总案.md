> **设计主题：一灯启幕，一影逐日，一杖成林。**  
> **修订日期：2026-10-19（北京时间）｜基础版本：用户提供的 V2.1 总案**  
> **用途：视觉定向、界面制作、剧场表现、资源筛选与后续实施交接。**  
> **本次成果：将图一正式纳入主菜单视觉方案，修订设计文档；工程接入与游戏验收仍属后续工作。**

本方案将图一确定为《灯影山海》的**主菜单视觉基准**：保留帷幕、木构、纸面、金饰、标题和青绿山水组成的舞台画面，以可交互控件重建菜单。它既是游戏入口，也应让玩家在开始前理解作品与“灯、影、戏”的关系。

## 1. 作品定位与玩家承诺

### 1.1 一句话定位

**玩家作为复演者，在一座久未开演的影戏台上，以灯为日、以影为夸父，通过三次光影互动，把未完成的《逐日》演到弃杖化林。**

作品最需要被看见的创新，是玩家同时理解“幕后如何操纵”和“幕上为何改变”，并看到自己的最终落杖状态连续长成林影。菜单与环境负责建立情绪、方向和文化辨识度，核心记忆点仍落在玩家动作上。

### 1.2 三条设计主线

1. **灯影关系清楚。** 可操作灯具、皮影、操杆与幕上投影能够建立直观因果；实际主投影来自 UE Movable 光源与可投影皮影。
2. **一座剧场逐步苏醒。** 三次互动复用同一套机制，逐步恢复色彩、声音、台翼和林影，不通过新增任务延长流程。
3. **从入口到落幕风格一致。** 菜单采用红帷幕、暖纸色、金饰与青绿山水；游戏中提取对应的台口、灯罩、题签与远景色彩，使入口画面能在实际剧场中得到呼应。

### 1.3 当前版本范围

| 必须具备 | 表现范围内可调整 | 范围外候选 |
|---|---|---|
| 标题入口、三互动、高潮、重演与退出 | 菜单微动效、题签样式、台翼装饰、可见远景层次 | 开放世界、完整村落、山林探索、第二戏台 |
| 可靠输入、中文提示、局部复位、流程重启 | 少量不参与判定的风、尘、枝叶与光色变化 | 精卫、刑天、烛龙可玩章节；支线、收集、NPC |
| 正式地图可运行、Development/Shipping 验证 | 已有免费资产的材质统一、摆放和构图 | 新账号系统、云存档、复杂关卡选择、非必要插件 |

范围外内容保留为讨论条目，不在菜单放“即将开放”承诺，不因为提前完成某个里程碑而自动进入本版。

### 2.2 色彩与材质

以下为便于制作的建议色值，并非从原图进行仪器级取样：

| 用途 | 建议色 | 使用原则 |
|---|---|---|
| 主要按钮与重点 | 朱红 `#A92D20` | 全屏同一时刻只有一个主要操作强亮 |
| 选中描边、灯火 | 暖金 `#D9A441` | 控制高光面积，避免整列按钮同时发光 |
| 文本底板 | 宣纸 `#F1DFC0` | 使用稳定的浅底承载深色文字 |
| 正文与普通图标 | 墨褐 `#2D2118` | 保证小字可读，避免用纹理侵蚀字形 |
| 山体与次要信息 | 青绿 `#3F6563` | 主要用于远景和弱强调，不与主按钮竞争 |
| 禁用状态 | 灰褐 `#776B5C` | 配合禁用标记和文字解释，不能只降低透明度 |

标题可以保留书法气质；按钮、说明、设置和提示使用已核验许可且覆盖所需汉字的字体。不能直接推断图一所用字体的名称和授权。现有项目中已有中文字体引用，可优先复用，并检查正式资源路径与 Cook 引用。

### 2.3 布局与适配

以 1920 × 1080 作为排版参考画布，原图仅作为构图依据，不以 1672 × 941 的像素坐标直接硬编码按钮热区。

| 区域 | 建议占位 | 约束 |
|---|---|---|
| 菜单列 | 左侧约 4%–24% 宽度，纵向约 18%–74% | 六行间距一致，点击区域覆盖牌匾正文区域 |
| 标题 | 画面上部居中，约 31%–70% 宽度 | 保留与日轮的关系，不被弹层以外内容遮挡 |
| 场景主视区 | 画面中部与右上 | 用于山海画卷，不堆叠统计、任务或公告 |
| 说明牌 | 右下约 74%–97% 宽度，约 59%–91% 高度 | 长说明进入独立面板，常驻牌只放短文 |
| 安全区 | 交互内容距屏幕边缘至少约 3% | 装饰可以出血，文字和按钮不能被裁掉 |

- 优先验证 1280 × 720、1920 × 1080、2560 × 1440；再检查 16:10 与 21:9 窗口。
- 16:10 与超宽屏优先完整保留 16:9 主画布，空余区域使用同色边饰，不直接裁掉菜单或把按钮拉伸。
- 全屏画面与控件必须使用同一布局变换；不能背景缩放后，透明热区仍停留在旧坐标。
- 1080p 下按钮字建议约 30–36 px、正文约 24–28 px；实际以引擎 DPI 与 720p 实屏阅读为准。
- 原图不能凭放大变成原生 4K 清晰素材。先完成 1080p 阅读与操作验证，高分辨率时优先保证独立文字与边框清晰。

### 2.4 按钮状态

| 状态 | 表现 | 行为 |
|---|---|---|
| Normal | 暖纸底、墨褐字、细金边 | 可交互但不强亮 |
| Hover / Focus | 朱红底、暖金描边、清晰焦点标记 | 鼠标与键盘获得同等反馈 |
| Pressed | 边光稍收、明度轻降 | 不改变布局和点击位置 |
| Disabled | 灰褐字、去发光、禁用符号 | 无点击回调，并在邻近说明中解释原因 |
| Busy | 短文案“舞台准备中……” | 入口请求处理期间阻止重复启动 |

图一把“开始游戏”画成永久高亮。正式 UI 需要消除底图中的固定亮态，由真实焦点控制；焦点移到“游戏说明”时不能出现两个同等强亮按钮。建议状态过渡为 0.12–0.20 秒，避免缩放晃动。

### 2.5 微动效与声音

首版采用静态绘景＋按钮状态即可成立。可选增强仅包括轻微灯火呼吸、低幅帷幕摆动和缓慢云层变化；没有分层素材时不强行把整图扭曲成动画。

进入、聚焦、确认、返回分别使用少量声音，快速划过按钮不得叠成连续噪声。声音只是辅助，静音时所有功能状态仍应明确。动态装饰不得影响点击位置，也不得抢过标题和当前焦点。

## 3. 菜单内容与交互闭环

### 3.1 六个菜单位置的正式定义

保留图一六行布局，但对不符合当前体验的名称和含义进行修订。以下为本版设计规格，非当前代码完成情况。

| 原图文字 | 正式显示建议 | 功能与前置条件 | 当前实施状态 |
|---|---|---|---|
| 开始游戏 | 开始游戏 | 从标题进入《逐日》第一段；仅在舞台就绪时可用 | 现有开始接口可复用；新皮肤待接入 |
| 继续游戏 | 继续游戏 | 仅用于仍在内存中的有效暂停会话；冷启动时禁用 | 暂停/继续待实现；无跨次存档承诺 |
| 章节选择 | 演出篇章 | 查看三段题签和一句话介绍；不跳关、不切地图 | 只读介绍页待制作 |
| 游戏说明 | 游戏说明 | 玩法、当前实际键位、复位与文化说明 | 页面待制作，键位需核对 |
| 设置 | 设置 | 主音量、窗口模式、已支持分辨率；可返回 | 功能和显示回退待验证 |
| 退出游戏 | 退出游戏 | 标题页正常退出；进行中先说明会放弃当前演出 | 现有退出接口可复用 |

“演出篇章”介绍页只列“引日启幕、逐光成形、杖落成林”，用来建立三段结构，不出现未实现神话或“制作中”按钮。该设计遵守当前版本不增加关卡选择的约束。

**继续游戏的确定规则：**

- 未接入暂停生命周期前始终禁用，提示“暂无可继续的演出”。
- 首版继续仅恢复当前运行中的暂停会话，退出程序后不保留进度；玩家在说明页能看到这条规则。
- 若后续另行批准本地存档，再单独定义版本兼容、保存点与失败恢复；不能把读取一个布尔值当作完成了可恢复存档。

### 3.2 图一右下角文案调整

图一现有文案包含“探索山海异境”“揭开神话背后的真相”，容易让玩家期待开放探索或真相调查。正式版改为与实际玩法对应的短文：

> **游戏说明**  
> 走进久未开演的影戏台，接续未完的《逐日》。  
> 移动灯光，调整皮影，让幕上的故事继续。  
> 以灯为日，以影为夸父，亲手演完这一场戏。

副标题建议从“光影神话解谜之旅”调整为 **“以灯为日 · 以影为夸父”**，使主题与操作对象直接对应。原图在文档中保持不改，正式美术拆分时替换这两处文字。

焦点改变时，说明牌可显示以下短句：

| 焦点 | 说明牌内容 |
|---|---|
| 开始游戏 | 开始一场约 5–8 分钟的《逐日》复演。 |
| 继续游戏 | 返回当前暂停的演出；关闭程序后不会保留本次进度。 |
| 演出篇章 | 了解同一场戏中的三个段落。 |
| 游戏说明 | 查看灯、偶、幕的关系与实际操作方式。 |
| 设置 | 调整声音和显示，返回后继续当前操作。 |
| 退出游戏 | 离开这座戏台。 |

### 3.3 鼠标、键盘与面板导航

1. 标题页舞台就绪后，默认焦点落在“开始游戏”；就绪前显示等待状态，不能提前触发流程。
2. 鼠标悬停与键盘上下选择共享同一视觉焦点；Enter 确认、Esc 返回当前子页。具体输入接入必须先核对现有上下文，不能占用谜题调整键。
3. 功能面板打开时，背景菜单停止接收输入。关闭后焦点回到原按钮，不回到不可见控件或游戏世界。
4. 禁用项不参与正常键盘确认路径；无法悬停的键盘用户也能在常驻短说明中看到不可用原因。
5. 开始与重演进入忙碌状态后，重复点击只产生一次有效请求。请求失败恢复可操作菜单并显示短提示。
6. 游戏中打开暂停界面后，灯、偶和角色不能继续接收操纵输入；恢复时清理残留按键，避免按住 A/D 打开菜单后对象继续滑动。

### 3.4 暂停、结束和设置

**暂停页：**保留当前舞台画面，加深色薄遮罩和同风格纸牌，提供“继续演出、游戏说明、设置、重新开始、退出游戏”。它不直接改写 Director 的成功或幕次。重新开始需要显示“将从第一段重新演出”的确认；取消后返回当前暂停态。

**结束页：**真实林影演出完成并收到既有完成事实后，保留成林结果，只显示“重新复演、游戏说明、退出游戏”。不立即用主菜单全屏山水盖住高潮，不把结尾重演伪装成有存档的继续。

**设置页：**首版仅包含必要项目。音量变化可立即试听；分辨率/窗口模式需有应用与恢复机制，建议 15 秒内未确认则回退。无法完成回退验证的显示项不开放为可点击功能。不同分辨率下能关闭设置页，比增加更多图形选项优先。

```text
                  └→ 说明/篇章/设置 ─→ 返回                 └→ 重演请求
                                        │                         │
                                暂停 ↔ 继续                 重载同一主地图
```

这是界面流程图，不是第二套谜题状态机。暂停、面板和焦点是本地 UI 状态；幕次、Holding、Resolve 和 Complete 仍以既有玩法事实为准。

## 4. 图一落地为 UE 界面的最小方案

### 4.1 素材拆分

| 交付素材 | 用途 | 唯一负责人 | 验收重点 |

| 无交互文字与固定亮态的背景绘景 | 主菜单背景 | 队友 | 保留原构图，不遗留按钮旧字或重影 |
| 标题标识 | 标题与日轮构图 | 队友 | 缩小可读，来源或制作记录明确 |

| 六类图标与说明牌边框 | 导航和说明 | 队友 | 轮廓统一，正文区域留白充足 |
| UMG 文字、点击区、焦点与页面 | 功能与适配 | 项目负责人 | 所有文字可更新，所有入口有返回路径 |

优先由队友按图一交付可复用的清洁底图与牌匾部件。若只有当前扁平 PNG，开发样机可以把真实控件覆盖在对应区域进行构图验证，但必须标明“临时接入”；原图中的固定字、固定高亮或说明残影没有清除前，不作为正式交付。无需为此购买素材或生成服务。

正文只命名已查到的接口；暂停、返回面板和设置操作是待实现职责，不伪造已经存在的 Blueprint 节点。

### 4.3 职责、通信与生命周期

| 对象 | 拥有的数据与权限 | 生命周期 / 清理 |
|---|---|---|
| 入口 Widget | 文案、按钮状态、当前子页、视觉动效 | 控制器创建和移除；构造绑定，销毁解绑 |
| 现有本地 PlayerController | 菜单请求、输入模式、鼠标、键盘焦点与请求防重 | 随当前世界结束清理；重演不遗留旧 Widget 引用 |
| Puzzle Director | 三段顺序、逻辑判定、成功与演出完成事实 | 沿用当前世界和 Token 合同；UI 不写这些状态 |
| Stage Presentation | 把既有事实转成镜头、声音与表现事件 | 显式注册与解绑；拒绝过期异步回调 |
| Stage Environment | 同一剧场的环境表现状态 | 由 Stage 显式调用；不读 Director、不 Tick 扫描 |

依赖方向：

```text
Widget ──按钮意图──→ 现有 PlayerController ──既有受控入口──→ 玩法流程
Widget ←─显示快照─── 现有显示/入口链 ←─────── 已成立的玩法事实
Stage Presentation ──环境状态──→ Stage Environment
```

按钮使用已知控制器引用调用；事实变化复用已有通知链。稳定的一对一关系不增加全局消息总线，不通过 `GetAllActorsOfClass` 找对象，不用 UI Tick 反复读取世界。所有新增状态仅为本地单机界面状态，不新增网络复制、持久化进度或新的谜题权威。

### 4.4 按顺序实施

1. **记录基线。**项目负责人记录当前入口、输入、主图和可运行包，备份将修改的源文件与资产；保留用户未提交改动。
2. **完成静态换肤。**队友交付拆分素材；负责人在隔离开发入口中接入背景、标题、按钮、说明牌和焦点。先验证点击区及 720p/1080p。
3. **复用已验证入口。**开始、重演、退出连接现有请求接口；保留 Waiting、Start、Hidden、End、Reloading 的正确语义。
4. **补只读页面与必要设置。**说明页键位对照实际输入；演出篇章只读；设置验证应用、取消、回退与关闭。
5. **单独验证暂停。**核对游戏时间、Holding、Sequence、声音和 UI 导航在暂停中的行为；暂停期间不能偷偷满足保持时间，恢复不能跳过落杖接触。
6. **接回正式入口。**确认主图仅加载一套菜单，Gameplay HUD 与菜单不重叠，焦点和鼠标按状态恢复。
7. **检查引用和包内行为。**正式 UI 不依赖临时目录；特别核对已有 Dev 路径中文字体引用，按实际依赖统一迁移或明确保留并验证 Cook，不盲删字体。

### 4.5 暂停与异常的特别约束

暂停不是“打开一张不透明图片”。若游戏时间、Holding 或 Sequencer 仍在前进，玩家会在菜单背后过关或错过成林。接入时必须验证：暂停前后灯偶位置一致、保持累计不增加、接触与完成事件不丢失，恢复后输入无残留。

开始失败、地图重载失败、Widget 重建、反复打开说明和退出世界，都要释放当前绑定与临时引用。地图重载期间到达的旧 Token 或旧 Widget 回调不得推进新一局。需要连续恢复的中断，使用既有统一终态/恢复路径；尚未提供该能力时记录为缺口，不自行复制流程。

## 5. 剧场空间与画面统一

### 5.1 空间层次

```text
不可探索远景：青绿远山 / 云雾 / 天色 / 少量远处轮廓
                          ↑ 台口或窗洞构成的视线
简化台前：前排长凳 / 栏杆 / 少量落尘，服务观看关系
                          ↑ 半透明幕布
核心戏台：主灯 ↔ 夸父皮影与操杆 ↔ 幕布 ↔ 目标影形
             左台翼：锣鼓角       右台翼：皮影挂架
                          ↑
                    幕后操作区 ← 入场短廊
```

先测量现有幕布、主灯、皮影和落杖锚点的真实范围，再围绕它们补齐建筑。取消原稿固定 40 × 30 × 18 m 剧场与 20 × 12 m 戏台的要求；这些未经测量的数字不能倒逼移动谜题 Actor。

### 5.2 各区最小内容

| 区域 | 最少需要表达的内容 | 玩家与镜头的关系 |
|---|---|---|
| 入场短廊 | 《逐日》题签、一盏引路灯、可见的幕边 | 短距离即可看见下一步，不增加大厅探索 |
| 幕后 | 灯轨、操偶区、操杆、幕布背面 | 核心可玩空间，操作对象轮廓清楚 |
| 左右台翼 | 锣鼓角、影偶挂架、布箱中选必要组合 | 提供文化信息与空间边界，不可收集 |
| 台前 | 少量座椅、栏杆与台口 | 给出“这里曾经有人观看”的证据 |
| 远景 | 山体、雾层、少量枝叶或建筑轮廓 | 只服务视线和氛围，不增加导航目标 |

近景触及或贴近的物件使用真实几何与合适碰撞；不可接近的远景可使用低成本几何或绘景。菜单上的整幅山海画卷不需要逐物建成三维场景。

### 5.3 从明亮菜单到沉寂剧场

主菜单可以明亮绚丽，开场剧场需要克制而沉寂。两者通过同样的木色、帷幕、灯罩和题签衔接。开场压低远景和装饰亮度，但保留道路、可交互物和幕布的可读性；不能把“沉寂”做成玩家看不见目标的全黑画面。

菜单在同一主地图的入口阶段显示。点击开始后，可用短淡化让绘景退去，显露真实剧场的既有入场机位；不需要新增外景漫游镜头。任何新相机过渡都由既有相机所有权合同接入，任一时刻只有一个最终 POV 所有者。

### 5.4 环境响应

| 环境状态 | 事实来源 | 可见表现 | 限制 |
|---|---|---|---|
| Dormant | 入场初始化 | 灯偏、影停、台翼低亮 | 第一目标必须可发现 |
| SunAwakened | P01 完成 | 幕边第一层暖金，题签被照亮 | 不提前点亮全场 |
| ChaseAwakened | P02 完成 | 台翼纹样与少量乐器进入视线 | 不新增寻找物件任务 |
| FinaleReady | P03 对应既有保持/解决表现阶段 | 日轮与杖尖聚焦，环境收束 | 必须按当前合同映射，不能自行提前宣布成功 |
| ForestComplete | 已验证接触与成林演出链 | 林影自杖尖延展，台前和远景完成显现 | 结尾菜单等真实流程 Complete 后出现 |

原稿“门外枯树复苏”改为可选的同场景表现：只有当现有机位看得见、且不遮挡核心林影时，才由 `BP_DYStageEnvironment` 响应已经成立的成林阶段。优先完成幕上林影向柱梁或地面的延续，不专门建外景区域或第二个反应管理器。

## 6. 三段演出、叙事与节奏

### 6.1 可核算的时间预算

计时口径为点击“开始游戏”后至结束页出现，包含入场、操作和演出；标题停留、主动暂停及阅读设置不计入。以下是设计预算，需通过盲测验证，不直接改动现有参数。

| 环节 | 预算 | 玩家获得的信息 |
|---|---:|---|
| 入场与第一目标 | 30–40 秒 | 知道这是一出未演完的戏，找到第一盏灯 |
| P01 引日启幕 | 55–75 秒 | 发现移动灯会改变影子 |
| 第一段过渡 | 10–15 秒 | 看见自己的操作唤醒戏台 |
| P02 逐光成形 | 80–100 秒 | 理解灯与皮影需要协同 |
| 第二段过渡 | 12–18 秒 | 准备综合已学动作 |
| P03 杖落成林 | 100–135 秒 | 用既有灯、偶、姿态形成最终构图 |
| 高潮与收束 | 40–60 秒 | 看到落杖连续导致成林 |
| **合计** | **327–443 秒，即 5 分 27 秒–7 分 23 秒** | 上限距 8 分钟保留 37 秒缓冲 |

若首次玩家超时，先分析迷路、目标不清、键位不明或演出等待，不因时间压力随意放宽已验证容差。需要调整判定参数或演出合同的，列出实测原因后由负责人确认。

### 6.2 三次互动的学习曲线

| 演出 | 学习目标 | 操作组合 | 反馈重点 |
|---|---|---|---|
| 引日启幕 | 发现规律 | 主灯的一个主要自由度 | 灯移动与日轮/影形变化直接对应 |
| 逐光成形 | 协同控制 | 同一主灯＋夸父位置、朝向或既有姿态 | 清楚区分“灯已接近”与“偶尚需调整” |
| 杖落成林 | 综合运用 | 同一灯、同一夸父与已经学过的姿态 | 保持最终构图，连续进入落杖与成林 |

三段使用同一套核心组件与输入语法。第三段的戏剧性来自组合、声音与演出，不增加新按键、不建立更复杂的物理识别，也不强迫玩家学习精细骨骼编辑。

### 6.3 叙事文字层级

- **菜单：**使用第 3 节的短梗概，建立“复演者、未完《逐日》、灯偶幕”的最小认识。
- **开场：**沿用已定稿的两张短卡，总计约 4–7 秒并包含在入场预算内；原典短引与团队引导语分别标注。当前文档不新增 10–20 秒强制过场。
- **段间：**只展示三段题签，不添加旁白剧情解释或长文本任务。
- **结尾：**成林后才回收“弃杖化林”的原典意象，并以“灯影未息，故事仍在人手中”收束。
- **说明页/片尾：**解释作品是借《山海经》意象进行创意改编；来源、许可与 AI 使用另行列明，不宣传为文物复原或某流派正统复现。

### 6.4 不可打断的高潮因果

```text
玩家完成 P03 最终灯偶构图
→ 既有逻辑确认并冻结必要终态/身份
→ 从该状态继续落杖
→ 杖尖接触成立
→ 林影从接触位置生长
→ 舞台环境回应
→ 既有流程确认演出完成
→ 显示结束页
```

不能在 Resolve 当帧就切到另一幅树林，也不能通过黑屏换构图掩盖落杖位置变化。跳过或中断演出时依照既有合同收敛到一致终态，既要防止重复生成，也要防止结束菜单提前挡住关键因果。

### 6.5 游戏内 UI 与声音

主菜单装饰不整套搬进游戏 HUD。游戏中仅保留当前题签、交互对象、实际按键、接近目标的趋势和必要保持反馈；纸牌与金边控制在画面边缘，让幕上结果成为视觉中心。

靠近、可操作、调整边界、趋势改善、Holding、中断和成功，都需有可见反馈。声音按离散状态或 Progress 分段变化触发，避免每帧进度连发。关闭音频后仍能完成三次互动；开启音频后，接触声、枝叶声与演出时序吻合。

### 9.3 遇阻时的简化顺序

1. UI 动效影响稳定性：移除装饰动效，保留静态绘景与真实交互反馈。
2. 原图无法直接拆分：用同构图的临时控件验证流程，由队友补干净部件，不把有残字的样机列为正式完成。
3. 新远景影响阴影或帧率：减少远景密度、动态光和雾，优先保住主灯投影、目标轮廓和实际操作。
4. 资源造型不合：复用已有结构、缩减可见范围；不采购、不新装插件、不扩展场景。
5. 暂停或设置未通过：明确列为未完成并保留可用基线；不能因按钮已画好而宣称菜单闭环完成。
6. 完整流程失败：停止装饰性新增，定位失败并回归验证，不用脚本跳过谜题替代用户通关。
