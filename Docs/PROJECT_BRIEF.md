# PROJECT BRIEF｜项目简报

## 1. 参赛与项目背景

《灯影山海》拟参加 **2026 年第十四届全国大学生数字媒体科技作品及创意竞赛“虚幻引擎（UE）作品创作”赛项**。该赛项面向虚幻引擎在游戏开发、虚拟现实、数字孪生、虚拟展陈、文旅体验、虚拟制片和实时交互等领域的应用，鼓励参赛团队发挥 UE 在实时渲染、场景构建、交互开发和性能优化方面的技术优势。

本项目主要对应赛项中的 **“基于 UE 的游戏与互动体验”** 方向，同时体现“实时渲染和交互探索”的技术特征。作品将以可运行的 Windows 游戏 Demo 为核心成果，而不是仅展示静态渲染画面。玩家通过亲自操纵灯具与皮影改变幕布上的实时影像，使传统皮影艺术意象从被动观看对象转化为可参与、可反馈、可完成的互动叙事体验。

项目的参赛价值不在于堆叠功能，而在于围绕“光源即玩法，影子即角色”形成一条完整且可验证的 UE 应用链路：玩家输入驱动受限对象，实时灯光与阴影呈现视觉结果，独立逻辑参数保证谜题稳定，Blueprint 与 Sequencer 将成功结果接入叙事演出，最终通过 Windows 打包、盲测和性能验证形成可现场体验、可录制展示的完整作品。

### 与赛项要求及评审重点的对应关系

| 赛项关注点 | 《灯影山海》的回应 |
|---|---|
| 引擎应用深度 | 使用 UE5 的实时灯光与阴影、材质、动画、Enhanced Input、C++、Blueprint 和 Sequencer，共同支撑核心玩法与演出 |
| 系统完成度 | 在单一戏台中提供可从开场走到结尾的三次递进互动、高潮演出、重置、结束界面和 Windows 可运行包 |
| 交互逻辑 | 玩家调整灯具与皮影后，幕布影像立即变化；谜题采用参数容差、趋势反馈和持续确认，形成清楚的操作—反馈—完成因果链 |
| 运行稳定性 | 将视觉阴影与玩法判定分离，避免画质、分辨率和阴影差异直接造成流程失效；关键状态提供调试、重置和恢复方式 |
| 实时渲染质量 | 以幕布、灯具、皮影轮廓、材质变化和高潮演出建立统一的光影视觉语言，并为录屏固定画质配置 |
| 性能优化 | 控制动态阴影对象与实时捕获成本，在目标电脑进行 1080p 性能测试、分阶段打包和连续通关验证 |
| 应用价值 | 以交互方式呈现中华传统皮影艺术意象，使文化视觉元素成为玩法、叙事和技术实现的统一载体 |
| 来源与授权 | 对第三方模型、插件、素材、字体、音频和代码登记来源、许可与使用位置，未经核验的内容不进入最终 Demo 或视频 |

2026 年官方评分共 100 分：选题价值与导向 10 分、创新性与原创贡献 25 分、技术实现与规范 25 分、完成度与可验证性 20 分、应用与传播价值 10 分、展示与答辩 10 分。官方同时明确不简单以技术复杂度、代码量或功能数量论优劣。因此本项目按以下顺序取舍：

| 技术实现与规范（25） | 以 UE5 实时阴影呈现、C++ 稳定判定、Blueprint/Sequencer 演出构成完整链路 | 架构图、调试界面、关键源码/蓝图截图、性能数据 |
| 完成度与可验证性（20） | 坚持单戏台、三互动、一个结尾；优先跑通、打包和盲测 | 连续通关录像、Windows 包、测试记录、问题闭环 |
| 选题价值与导向（10） | 把皮影与《山海经》从展示对象转成可参与的数字叙事体验 | 文化来源说明、创意改编边界、体验目标 |
| 应用与传播价值（10） | 面向展陈、科普和文旅体验说明可迁移价值，但不在 Demo 中扩建新场景 | 应用设想页、现场体验流程、传播短片 |
| 展示与答辩（10） | 前 30–60 秒就呈现“移动灯—影子变化—叙事推进”的核心因果 | 演示脚本、无剪辑操作片段、故障降级方案 |

同分情况下优先比较创新性、技术实现、完成度与可验证性、展示与答辩，因此任何新增内容都必须先证明能增强这四项之一。完整调研与历届案例见 `COMPETITION_BENCHMARK.md`。

## 3. 一句话提案

玩家作为“复演者”走入一座久未开演的小型影戏剧场，以灯为日、以影为夸父，通过“引日启幕—逐光成形—杖落成林”三次逐步升级的光影互动，把停在夸父尚未落杖时的最后一出《逐日》重新演完。

### 3.1 最小故事背景

- 戏台是山野边缘的一座虚构小剧场，不指向具体朝代、地域或真实遗址；
- 最后一出《逐日》停在落杖之前，灯、偶、锣鼓和幕布保持未完成状态；
- 玩家身份只有“复演者”，动机是把未完的戏演完；
- 没有 NPC、复杂身世、对话树和拯救世界任务；
- 故事通过环境、灯偶关系、声音恢复和三次操作成立，开场最多两句短字幕。

## 4. 体验目标

玩家离开 Demo 时应记住三件事：

1. 自己移动的不是普通机关，而是决定影子形态和叙事的“光”；
2. 幕后简单的灯与皮影，在幕布上形成了有生命感的山海世界；
3. 最后的演出是前三次亲手完成的结果，而不是与玩法无关的一段视频。

## 5. 设计支柱

### 光源即玩法

光源的位置、距离或角度必须直接改变玩家看到的影子，并参与谜题判定。灯光不是纯装饰。

### 影子即角色

玩家主要关注幕布上的轮廓、动作和关系。幕后实体用于解释操作，幕上影子承担戏剧表现。

### 文化即机制

“夸父逐日”不是背景介绍或装饰标签：灯承担“日”的视觉与玩法作用，夸父皮影的追逐姿态承担目标构图，最终手杖化林成为对前三次操作的叙事回报。三者必须由同一套交互与演出链路连接。

### 三次互动只做一次学习

三次互动复用同一组基础操作：选择、移动/旋转、观察、微调、保持确认。后续通过组合条件和演出压力增加深度，不引入完全不同的小游戏。

### 短流程必须有完整起承转合

5–8 分钟内完成：进入与吸引、无文字或少文字教学、两次递进、第三次合演、高潮回报、明确结束。

### 小戏台承载大世界

地图不追求面积，而通过入场—幕后—台翼—幕布—台前的纵深、上方梁架、不可探索远山、逐段苏醒的灯光与声音，以及 Finale 越过幕布边界的林影，制造“一方小幕承载山海”的空间感。周边环境不新增玩法，只加强场所可信度、文化媒介特征和演出尺度。

## 6. 文化创意与原创贡献

《灯影山海》不把“皮影”“《山海经》”或“UE 实时阴影”单独当作原创点。相邻竞赛作品已经出现皮影美术、皮影 AI 创作、皮影 VR 展示和《山海经》虚拟场景，商业游戏也已有影形匹配和控制光源改变影子的玩法。

项目可辩护的原创贡献是：

> 把“夸父逐日—弃杖化林”的文化动作、皮影戏的灯—偶—幕结构、UE 实时光影和独立参数判定组织成一条由玩家亲手完成的短篇互动演出。

| 文化意象 | 玩法表达 | 演出回报 |
|---|---|---|
| 日 | 玩家操纵主灯的位置或角度 | 日轮归位，戏台第一次被唤醒 |
| 逐日 | 玩家协调灯与夸父皮影的位置、方向和姿态 | 追逐关系成形，鼓点和色彩继续恢复 |
| 弃杖化林 | 玩家完成最终持杖/落杖构图 | 林影从手杖落点生长并汇入高潮 |
| 皮影戏 | 玩家从幕后操纵灯与偶，同时观察幕上结果 | 镜头揭示“幕后实体—幕上影像”的实时因果 |

文化依据与边界：

- 神话文本以《山海经》相关篇目为主要来源；
- 皮影结构参考纸/皮革人物、操杆、背光幕布、音乐与表演的基本特征；
- 戏台沉寂、三段解谜、光色恢复和高潮编排属于作者创作改编；
- 不宣称文物复原、历史复刻或某地域皮影流派的正统再现；
- 若使用具体地域造型、纹样、唱腔或乐器，必须记录来源、改编与许可。

详细竞品比较、优势、弱点和不可使用的宣传说法见 `COMPETITION_BENCHMARK.md`。

## 7. 目标受众与场景

- 数字媒体、游戏或创意作品评审
- 现场体验者与演示视频观众
- 对皮影、美术风格和互动叙事感兴趣的普通玩家

作品必须兼顾“现场可玩”和“视频可读”：操作反馈要清楚，影子变化要能被镜头捕捉，高潮画面要在短视频中迅速成立。

## 8. 最终范围

### 必须完成

- 一个可以从入场走到落幕的连续小剧场：短廊、幕后、台翼、幕布、简化台前和远景层
- 一套稳定的灯具操纵方式
- 一套可调整位置/朝向/姿态的皮影交互
- 三个复用统一框架的谜题实例
- 实时视觉阴影
- 与视觉渲染解耦的逻辑判定
- 每次互动的引导、趋势反馈、成功反馈与重置
- 一段从玩家最终影形、杖尖接触点直接生长出来的“弃杖化林”高潮
- 能同时解释幕后操作与幕上结果的稳定操纵镜头，以及安全的 Sequencer 交接
- 微风、操作拟音、脚步/呼吸、锣鼓、吟唱和枝叶声构成的分层声音节奏
- 基础字幕/提示、结束界面和只在 Development 可见的判定/镜头/性能调试显示
- Dormant、SunAwakened、ChaseAwakened、FinaleReady、ForestComplete 五个可区分的环境表现状态
- Windows 可运行包与可用于剪辑的稳定录屏流程

### 有余量再做

- 低分辨率 Render Target Mask 轮廓相似度判定
- 更多窗外天气、观众剪影和次要环境微动
- 手柄支持或更细的辅助选项
- 额外幕后可观察细节

以上内容不得阻塞“必须完成”。

### 明确不做

- 第二个场景或可探索大地图
- 完整村落、可探索山林、博物馆展厅、第二座戏台和多房间后台
- 环境调查、收集品、NPC、对话树和支线任务
- 战斗、追逐、敌人 AI、数值成长
- 多分支剧情和多结局
- 联网与复杂存档
- 三种互不相关的谜题系统
- 依赖高风险渲染研究才能完成的核心流程

## 9. 单人制作职责

唯一人类作者与项目负责人：用户本人。

| 工作 | 唯一负责人 | 可使用的辅助方式 |
|---|---|---|
| 架构、C++、Blueprint、玩法与关卡 | 用户 | Codex 按批准范围实现、测试及文档辅助 |
| 皮影、戏台、幕布、道具、纹样与材质 | 用户 | 免费/开源资源筛选、文化依据核验、脚本化适配；不预设手工建模 |
| 动画、灯光、镜头与声音 | 用户 | 复用既有事件和参数，免费资源逐项核验 |
| 录屏、视频、封面和参赛材料 | 用户 | 免费工具、模板与素材；记录真实来源和 AI 使用 |
| 测试、许可、打包与最终提交 | 用户 | 自动核查辅助；真人体验与提交确认由作者负责 |

AI 不是制作成员；外部资产不冒称作者原创建模。未参与制作的测试者只提供盲测反馈。

## 10. 成功指标

### 可玩性

- 至少 3 名未参与开发的测试者中，大多数无需开发者代操作即可通关；
- 第一次核心操作在进入互动区后约 60 秒内被理解；
- 单次错误不会造成永久卡死，玩家可退出、重置或继续微调；
- 三次互动能被首次玩家理解为“发现规律—协同控制—综合运用”，且第三次不新增交互语法。

### 稳定性

- 目标演示电脑上连续完成三轮全流程，无崩溃、无流程阻塞；
- 打包版本中不存在依赖编辑器调试操作才能继续的步骤；
- 实时阴影质量降低时，逻辑谜题仍能完成；
- 核心交互有清晰的状态日志与 Development 调试显示，能证明参数判定不读取阴影像素；
- Finale 正常结束、跳过和中断后，输入、View Target 与树林最终状态一致。

### 表现

- 戏台、幕布、灯具和皮影形成统一风格；
- 场景在同一地图内清楚读作入场、幕后、台翼、台前和远景组成的完整小剧场；
- Dormant 到 ForestComplete 的五个状态能通过同机位截图清楚区分，但环境灯不削弱主灯关键阴影；
- 高潮结尾能明显复用或回应前三次互动形成的影像，林影从玩家造成的杖尖接触点开始；
- 录屏中无需文字解释也能看懂“移动灯—影子改变—完成目标”的因果链；
- 至少一段 10–20 秒无切镜画面同时看见幕后对象与幕上变化；
- 静音时仍可通关，开启声音时能听出接近、Holding、成功和化林高潮的层次；
- 不了解项目的评审在 60 秒内能说出“玩家把灯当作太阳，操纵夸父皮影追逐并完成演出”。

## 11. 关键风险与对策

| 风险 | 早期信号 | 当前竞赛版本对策 |
|---|---|---|
| 实时阴影效果漂亮但判定不稳 | 相同操作结果漂移、受画质影响 | 用参数区间完成逻辑判定，视觉阴影只负责呈现 |
| 操作精度要求过高 | 玩家反复微调仍不知道差在哪里 | 容差、吸附、趋势反馈和保持确认；降低自由度 |
| 美术资产延期 | M4 验收前仍有大量关键占位 | 优先锁定幕布、主灯、核心皮影；次要道具降级 |
| 动画/演出吞噬开发时间 | 主流程未通却在调镜头 | 先用占位 Sequencer 跑通，再替换动画和镜头 |
| 第三次互动变成新系统 | 需要新增大量类或输入 | 只组合已验证的灯光与皮影条件 |
| “成林”像通关后附加视频 | 落杖和树林之间发生黑屏、瞬移或无关切镜 | 冻结 P03 最终状态；杖尖接触帧同步重音和林影首帧；跳过时应用一致终态 |
| 双空间镜头看不清 | 幕后物体遮幕或只看见幕布结果 | M1 锁定三分之四操纵机位；先解决机位/遮挡，再加景深和镜头运动 |
| 音效频繁叠加或误导 | Progress 每帧触发、高潮提前进入 | Progress 离散分段并加冷却；Holding/Resolve/接触使用不同状态事件 |
| 场景像技术测试盒 | 画面只有幕布、灯和偶，缺少入口、台翼与前后纵深 | M1 同时灰盒连续剧场壳体；远景和台前采用低成本、不可探索方案 |
| 环境扩张吞噬范围 | 开始制作村落、山林、NPC 或环境任务 | 所有新增环境必须属于同一主地图并只服务演出；按环境止损顺序降级 |
| 故事只能靠说明文理解 | 需要长字幕解释玩家身份和戏台历史 | 用题签、空槽、未响乐器、灯轨磨损和三段恢复表达；开场最多两句 |
| 打包问题发现太晚 | 只在编辑器中测试 | 从 M1 起每个里程碑生成并验证独立 Development 包，M5/M6 验证 Shipping |
